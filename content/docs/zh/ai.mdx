这个项目按“人和 AI 共用一套工程约定”来设计。文档、Skills 和分支工作区都放在仓库里，Agent 不需要额外配置就能理解项目结构。

## 推荐的 Agent：OpenCode

项目最推荐的 Agent 是 [OpenCode](https://opencode.ai/)。它原生支持项目级 Skills，会自动发现 `.agents/skills/`，也可以直接使用 `skills` CLI 恢复技能包。

推荐的工作方式：

- 在项目根目录启动 `opencode`，让会话默认继承仓库上下文。
- 用 OpenCode 的 worktree 能力隔离功能分支，避免多个任务互相污染工作区。
- 把可复用的流程写成 Skill，而不是每次在提示词里重复说明。

## 项目内置的 Skills

Skills 是可复用的 Agent 指令包。它和 `node_modules` 一样属于“安装产物”，因此 **`.agents/` 不提交到 Git**：

| 路径 | 是否提交 | 作用 |
| --- | --- | --- |
| `.agents/skills/` | 否，已在 `.gitignore` 中忽略 | 安装后的 Skill 文件 |
| `skills-lock.json` | 是 | 锁定每个 Skill 的来源与哈希 |
| `package.json` 中的 `skills` | 是 | 提供 `skills` CLI |

所以刚克隆项目时并没有 `.agents/skills/`，需要从 `skills-lock.json` 恢复。当前锁定了 11 个 Skill：

| Skill | 来源 | 用途 |
| --- | --- | --- |
| `caveman-commit` | `juliusbrussee/caveman` | 生成压缩到意图的 Conventional Commits 提交信息 |
| `prisma-cli` | `prisma/skills` | Prisma CLI 命令、迁移、Studio、调试 |
| `prisma-client-api` | `prisma/skills` | Prisma Client 查询、过滤、事务 |
| `prisma-compute` | `prisma/skills` | Prisma Compute 部署（备查，本项目未使用） |
| `prisma-database-setup` | `prisma/skills` | 配置 PostgreSQL、MySQL、SQLite、MongoDB 等数据库 |
| `prisma-driver-adapter-implementation` | `prisma/skills` | 实现或修改 Prisma driver adapter（本项目使用 `@prisma/adapter-pg`） |
| `prisma-mongodb-upgrade` | `prisma/skills` | MongoDB 项目的 Prisma 升级决策（备查） |
| `prisma-postgres` | `prisma/skills` | Prisma Postgres 托管数据库操作（备查） |
| `prisma-postgres-setup` | `prisma/skills` | 通过 Management API 创建 Prisma Postgres（备查） |
| `prisma-upgrade-v7` | `prisma/skills` | Prisma v6 升级到 v7 的迁移指南 |
| `shadcn` | `shadcn/ui` | shadcn/ui 组件、registry 与样式规范 |

其中标记“备查”的技能随 Prisma 技能包一起锁定，当前项目不一定直接用到，但升级或切换数据库时会派上用场。

## 安装 Skills

Skills CLI 要求 Node.js 22.20 或更高版本。项目已经把 `skills` 放在 `devDependencies`，所以先安装依赖，再从锁文件恢复：

<Steps>

<Step>
### 安装项目依赖

```bash
bun ci
```

</Step>

<Step>
### 从锁文件恢复 Skills

```bash
bunx skills experimental_install
```

这个命令会读取 `skills-lock.json`，把 Skill 恢复到 `.agents/skills/`。它不会安装 npm 依赖，所以必须在 `bun ci` 之后执行。

</Step>

<Step>
### 验证安装结果

```bash
bunx skills list
```

应该能看到上表中的 11 个 Skill。OpenCode 会自动加载 `.agents/skills/`，不需要再复制到其他目录。

</Step>

</Steps>

`experimental_install` 仍是实验性命令。如果将来命令改名或不可用，可以按来源手动安装：

```bash
bunx skills add prisma/skills --skill '*' -a opencode -y
bunx skills add shadcn/ui --skill shadcn -a opencode -y
bunx skills add juliusbrussee/caveman --skill caveman-commit -a opencode -y
```

只有在新增、删除或更新 Skill 时才需要执行 `add` / `update`。这些操作会改写 `skills-lock.json`，请把锁文件的变更和代码一起提交；不要提交 `.agents/`，它是可以随时重建的安装目录。

## 使用 OpenCode 的 worktree

当任务需要独立分支、和当前会话并行开发时，可以让 OpenCode 创建 Git worktree，并把会话移动进去。OpenCode V2 提供了这些内置能力：

| 能力 | 说明 |
| --- | --- |
| `worktree_create` | 按名称创建 worktree，返回新目录 |
| `worktree_list` | 列出当前项目的 worktree |
| `worktree_remove` | 删除 OpenCode 记录的 worktree；`force` 会丢弃未提交改动 |
| `session_move` | 把当前会话移动到指定目录，在安全边界生效 |

在 TUI 里直接用自然语言描述即可：

```text
Create a worktree named "feat-ai-docs" and move this session into it.
```

worktree 的存放位置由 `opencode.jsonc` 的 `worktree.directory` 决定。默认放在 OpenCode 服务的数据目录下；如果希望集中管理，可以改成项目旁边的目录：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "worktree": {
    "directory": "../worktrees"
  }
}
```

相对路径以项目的主检出目录为基准。`session_move` 的移动会在安全边界生效，因此移动完成后再执行后续的安装和验证命令。

### 移动会话后要做的三件事

worktree 是一个全新的检出目录，`gitignore` 里的本地文件不会跟过去。移动完成后按顺序处理：

<Steps>

<Step>
### 重新安装 node_modules

```bash
bun ci
```

不要直接软链接主仓库的 `node_modules`：不同分支的依赖版本可能不同，原生模块和 `.bin` 也可能绑定到原路径。每个 worktree 单独安装最稳妥。

</Step>

<Step>
### 生成 Prisma Client

```bash
bunx prisma generate
```

`lib/generated/prisma` 被 Git 忽略，新 worktree 里不存在，不生成就无法启动应用。

</Step>

<Step>
### 软链接 .env.development

`.env.development` 包含真实密钥并且被 Git 忽略，建议软链接到主仓库的文件，而不是复制多份：

Windows PowerShell（在 worktree 根目录执行，目标换成你的主仓库路径）：

```powershell
New-Item -ItemType SymbolicLink -Path .env.development -Target C:\repos\template-nextjs-hucky\.env.development
```

macOS / Linux：

```bash
ln -s /path/to/template-nextjs-hucky/.env.development .env.development
```

Windows 创建符号链接需要开发者模式或管理员权限；如果环境不允许，可以临时复制 `.env.development`，但不要提交它。

</Step>

</Steps>

软链接的好处是密钥只有一份：修改主仓库的环境变量后，所有 worktree 立即同步，也不会因为忘记更新而出现“只在某个分支能跑”的问题。

### 清理 worktree

任务合并后，在 OpenCode 里说：

```text
List the worktrees for this project.
Remove the "feat-ai-docs" worktree.
```

如果 worktree 里还有未提交的改动，OpenCode 不会直接删除；确认不再需要这些改动时，才使用 `force`。删除前先提交或合并，避免丢失工作。
