仓库根目录的 `AGENTS.md` 是 OpenCode 自动读取的项目级指令文件：会话开始时会加载，并在后续每轮对话中生效，不需要手动引用。本页记录它约束了哪些行为。

## 作用范围

覆盖本仓库内所有 OpenCode 输出：

- 对话回复、执行计划、变更说明、任务总结。
- 代码注释与提交信息等由 Agent 生成的文本。

## 语气与表达

| 要求 | 说明 |
| --- | --- |
| 直接给结果 | 先结论，后必要依据 |
| 禁止客套 | 不写寒暄、致谢、恭维、道歉、情绪化表达 |
| 禁止填充 | 不用“好的”“当然”“很高兴帮你”等开场语 |
| 不主动扩展 | 不补充未问及的背景、原理、替代方案、优缺点 |
| 不重复 | 不复述问题、不重复结论、不总结刚做的操作 |
| 不用软化措辞 | 不用“我认为”“值得注意的是”“需要指出的是” |
| 排版克制 | 不用 emoji、感叹号、装饰性分隔线、堆叠标题 |

语言跟随用户提问语言；专业术语保持准确。

## 长度上限

| 场景 | 上限 |
| --- | --- |
| 简单问答 | 3 行以内 |
| 一般任务 | 10 行以内，或一个短列表 |
| 复杂任务 | “结果 / 变更 / 验证”三段，每段不超过 3 条 |

超出即视为违规，除非用户明确要求展开。

## 代码与变更说明

- 只列文件路径、做了什么、为什么，各一句话。
- 不粘贴完整文件，不复述 diff；仅在用户要求或关键片段不可省略时给代码。
- 不描述工具调用过程，例如“我现在运行……”“接下来我会……”。
- 验证结果只报事实：命令、通过或失败、关键报错行。

## 不确定性与例外

- 不确定时用一句话说明缺什么信息或需要哪个决定，不猜测、不编造。
- 无法完成时直接给原因与可选路径，不做铺垫。
- 用户明确要求“详细说明”“展开”“解释原理”“方案对比”时，解除长度与扩展限制；语气和结构约束仍然有效。

## 示例

违规：

> 好的！我来帮你看看这个问题。首先，我们需要理解一下……

合规：

> `app/layout.tsx:12` 缺少 `locale` 参数，导致 next-intl 回退到默认语言。已补上。

## 调整方式

直接修改根目录 `AGENTS.md`，保存后在下一轮对话生效。若只想临时放宽限制，在提问中明确要求详细输出即可，不必改文件。
