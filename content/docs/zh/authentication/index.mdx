本项目把身份认证完全交给 Logto，本地只保留三样东西：

- **`User`**：业务资料和授权关系，不保存密码。
- **`Session`**：应用自己的不透明会话，决定请求是否已登录。
- **RBAC**：角色与权限，由业务代码判断。

因此没有本地邮箱密码登录，也没有本地注册接口。所有用户都从 Logto 进入。

## 唯一的身份入口

| 项目 | 说明 |
| --- | --- |
| 登录入口 | 登录页的 `使用 Logto 登录` 按钮 |
| 凭据 | 完全由 Logto 管理（密码、社交登录、MFA 等） |
| 账号来源 | Logto 回调时创建或绑定本地 `User` |
| 会话 | 回调成功后由本应用签发 |

Logto 只负责“这个人是谁”，本应用负责“这个人能做什么”。业务代码不需要关心用户用哪种方式在 Logto 登录。

## 账号关联规则

`lib/logto-user.ts` 用 Logto 的 `sub` 作为唯一关联键：

1. 已存在 `logtoSub` 相同的用户：同步 `name`、`avatarUrl` 和已验证邮箱。
2. 没有绑定过，但本地有同邮箱的历史账号：绑定一次 `logtoSub`，保留该账号的角色和业务数据。
3. 都不存在：创建新的本地用户。
4. 没有已验证邮箱：使用 `<sub>@logto.local` 作为占位邮箱，避免和真实邮箱冲突。

<Callout type="warn" title="只信任已验证邮箱">
未验证的 Logto 邮箱不能用于绑定历史账号，否则攻击者可以在 Logto 填写他人邮箱并接管本地账号。当前实现只在 `email_verified === true` 时用真实邮箱做一次性绑定。
</Callout>

邮箱只是资料字段，用户在 Logto 改邮箱不会断开本地账号，因为关联键是稳定的 `sub`。

## 会话模型

本地 Session 采用不透明 token：

- 客户端只持有随机 token，保存在 httpOnly Cookie。
- 数据库只保存 `sha256(token)`，即 `Session.tokenHash`。
- `proxy.ts` 只做乐观检查（Cookie 是否存在、格式是否合法），不查数据库。
- 受保护页面的 layout 通过 `requireUser()` 查库，完成权威校验。
- 会话过期或用户被禁用时，服务端会删除会话并拒绝访问。
- 登出会删除本地 Session，并清理 Logto SDK 的 Cookie。

详见[会话与路由保护](/zh/docs/authentication/session)。

## 关键文件

| 路径 | 作用 |
| --- | --- |
| `app/api/auth/logto/route.ts` | 发起 Logto 登录 |
| `app/api/auth/callback/route.ts` | Logto 回调、映射用户、创建本地会话 |
| `app/api/auth/logout/route.ts` | 删除本地会话并清理 Cookie |

| `lib/session.ts` | Session 创建、校验、删除 |
| `lib/session-token.ts` | token 生成、哈希与格式校验（无 Prisma 依赖） |
| `lib/prisma.ts` | Prisma Client 单例 |
| `proxy.ts` | 国际化 + 乐观路由检查 |
| `prisma/schema.prisma` | User、Session、Role、Permission 模型 |

## 当前边界

- 本地没有注册、密码、验证码或找回密码流程，这些全部由 Logto 提供。
- 没有“解绑 Logto”或“查看已绑定身份”的界面。
- RBAC 数据模型已经建立，但还没有角色管理 UI 和授权 API；授权判断需要业务代码自己实现，详见 [RBAC 权限](/zh/docs/authentication/rbac)。
- 没有登录频率限制、审计日志和 MFA；这些能力应优先在 Logto 侧配置。增量升级建议见[演进与扩展](/zh/docs/authentication/evolution)。
