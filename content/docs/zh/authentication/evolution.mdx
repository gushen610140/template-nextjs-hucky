当前实现适合“一个 Logto 身份一个本地用户”的基础场景。下面按风险和收益排序，给出后续增量升级时需要考虑的内容。

## 当前边界

| 能力 | 当前状态 | 风险 |
| --- | --- | --- |
| Logto 登录 | 已实现 | 一个本地用户只能绑定一个 Logto 身份 |
| 本地密码 / 验证码 | 已移除 | 认证策略需要在 Logto 侧配置 |
| RBAC 模型 | 已建表 | 没有授权 API、管理界面和种子 |
| Session | 已实现 | 没有“登出所有设备”和审计 |
| 账号禁用 | 已实现 | 禁用后会拒绝登录并清理会话 |
| 邮箱变更 | 已由 `logtoSub` 处理 | 邮箱只是资料字段，不影响关联 |

## 1. 支持一个用户绑定多个身份

当前 `User.logtoSub` 只能保存一个 Logto 身份。如果以后要接入第二个 IdP，或者允许同一个用户绑定多个登录方式，可以增加身份表：

```prisma
model AuthIdentity {
  id                String   @id @default(cuid())
  provider          String   // "logto" | 其他 IdP
  providerAccountId String   // 该 IdP 的稳定用户 ID
  userId            String
  email             String?
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([provider, providerAccountId])
  @@index([userId])
  @@index([email])
}
```

同时给 `User` 增加：

```prisma
identities AuthIdentity[]
```

升级顺序：

1. 新增可空结构，不修改现有登录逻辑。
2. 在回调时回填 `AuthIdentity`。
3. 新逻辑优先按 `provider + providerAccountId` 查找。
4. 只有不存在身份记录时才按已验证邮箱合并。
5. 最后再决定是否移除 `User.logtoSub`。

<Callout type="warn" title="不要直接用未验证邮箱合并">
邮箱合并必须要求 `email_verified === true`。否则任何人都可以在第三方身份中心填写受害者邮箱，接管本地账号。
</Callout>

## 2. 验证码与无密码登录

认证已经交给 Logto，优先直接在 Logto 控制台启用邮箱验证码、社交登录或 MFA，而不是在本地重新实现。

如果确实需要本地 OTP，正确实现至少需要：

- 服务端生成 OTP，不使用客户端生成。
- 数据库只保存 OTP 哈希，不保存明文。
- 设置短过期时间，例如 5 到 10 分钟。
- 限制验证尝试次数，失败后作废。
- 按邮箱、IP、设备做速率限制。
- OTP 使用一次后立即删除。
- 发送失败时不泄露账号是否存在。

可以新增 `VerificationCode` 模型：

```prisma
model VerificationCode {
  id        String   @id @default(cuid())
  email     String
  codeHash  String
  purpose   String
  attempts  Int      @default(0)
  expiresAt DateTime
  createdAt DateTime @default(now())

  @@index([email, purpose])
  @@index([expiresAt])
}
```

不要恢复“任意 6 位数字通过”的占位逻辑。

## 3. 邮箱验证

邮箱归属由 Logto 验证，本应用只读取 `email_verified`。如果业务要求更强的证明，可以在 Logto 侧开启邮箱验证流程，再决定是否增加 `User.emailVerifiedAt` 用于限制敏感操作。

## 4. 会话加固

建议逐步增加：

- Session 轮换：登录或权限提升后创建新 token。
- “登出所有设备”：按 `userId` 删除全部会话。
- 定期清理过期会话，并为 `expiresAt` 建立索引。
- 记录登录时间、IP、User-Agent，支持会话列表。
- 对高敏感操作要求重新认证。

当前 `getSessionUser` 已经会在过期或用户禁用时清理会话，并且只选择安全字段。后续改动不要把内部关联字段一并返回。

## 5. 登录限流与审计

认证频率限制优先在 Logto 侧配置。应用侧仍应记录：

- 登录成功、失败、登出、角色变更的审计日志。
- 同一账号短时间多地登录的告警。
- 敏感操作的二次确认。

审计日志不要记录 Session token 或任何 IdP 凭据。

## 6. RBAC 管理面

当前只有表结构。建议按以下顺序补齐：

1. 种子角色和权限。
2. `lib/authz.ts` 统一授权判断。
3. 角色管理 API。
4. 用户角色分配界面。
5. 权限变更审计和缓存失效。
