Logto 是本项目唯一的身份中心。它负责登录界面和身份验证；本应用仍然使用自己的 `User` 表和本地 Session。

## 配置

在 `.env.development` / `.env.production` 中配置：

```ini
LOGTO_ENDPOINT=https://your-tenant.logto.app
LOGTO_APP_ID=your-app-id
LOGTO_APP_SECRET=your-app-secret
LOGTO_BASE_URL=http://localhost:3000
LOGTO_COOKIE_SECRET=a-long-random-string
```

- `LOGTO_BASE_URL` 必须与 Logto 控制台注册的 Redirect URI 的站点部分一致。
- Redirect URI 应配置为：

```text
http://localhost:3000/api/auth/callback
```

生产环境换成实际域名。回调位于 `/api` 下，不经过 next-intl 中间件，因此不需要语言前缀。

## 登录流程

1. 用户点击登录页的 `使用 Logto 登录`。
2. 浏览器访问 `/api/auth/logto?next=...`。
3. `next` 被写入短期的 `logto_next` httpOnly Cookie。
4. Logto SDK 的 `signIn` 重定向到 Logto 授权页。
5. Logto 回调到 `/api/auth/callback?code=...&state=...`。
6. `handleSignIn` 校验 `state`，用授权码换取 token，并把 token 写入 Logto SDK 自己的加密 Cookie。
7. `getLogtoContext` 读取 ID token 的 claims。
8. `upsertLogtoUser` 把 claims 映射到本地 `User`。
9. 创建本地 Session，写入 `session` Cookie。
10. 根据 `logto_next` 或默认语言跳转回站内页面。

## claims 如何映射到本地用户

`lib/logto-user.ts` 的规则：

| 情况 | 本地处理 |
| --- | --- |
| 已存在相同 `logtoSub` | 同步 `name`、`avatarUrl` 和已验证邮箱 |
| 没有绑定，但本地有同邮箱的历史账号 | 绑定一次 `logtoSub`，保留角色和业务数据 |
| 都没有 | 创建新 `User` |
| 没有已验证邮箱 | 使用 `<sub>@logto.local` 占位邮箱 |
| 并发回调同时创建 | 捕获 `P2002`，回查已创建的账号 |
| 邮箱已被其他 Logto 身份占用 | 退回占位邮箱，避免相互覆盖 |

### 为什么用 sub 而不是邮箱

Logto 的 `sub` 在用户生命周期内不变，邮箱却可能被用户修改。如果继续用邮箱做关联键，用户改邮箱后会被识别成新账号，甚至可能并入另一个同邮箱账号。`logtoSub` 唯一列解决了这个问题。

### 为什么使用占位邮箱

部分 Logto 实例只启用 username 登录，不提供已验证邮箱。此时如果拿未验证邮箱去匹配，本地已有账号可能被他人接管。`<sub>@logto.local` 使用稳定的 `sub`，既保证一个 Logto 身份对应一个本地用户，又不会和真实邮箱冲突。

<Callout type="warn" title="不要信任未验证邮箱">
只有 `email_verified === true` 才能参与历史账号的一次性邮箱绑定。修改这段逻辑前，先确认 Logto 是否已经完成邮箱验证。
</Callout>

## 登出

`POST /api/auth/logout` 会：

1. 删除本地 `Session`。
2. 清除 `session` Cookie。
3. 清除 Logto SDK 的 `logto_<appId>` Cookie，避免残留登录态。

如果用户还停留在 Logto 的全局会话中，再次点击 Logto 登录可能无需输入密码直接返回。这是 Logto 的 SSO 行为，不等于本地 Session 仍然有效。

## 当前限制

- 没有“解绑 Logto”或“查看已绑定身份”的界面。
- 一个本地用户目前只能绑定一个 Logto 身份。需要多身份绑定时，建议增加 `AuthIdentity` 表，详见[演进与扩展](./evolution)。
- Logto 回调失败时统一回到 `/login?error=logto`，没有细分错误码。
- 没有在本地缓存 Logto 的 access token。需要调用 Account API 或 Management API 时，应通过 `getAccessToken` / `getAccessTokenRSC` 显式获取。

## 调试清单

- Logto 控制台的 Redirect URI 是否是 `<LOGTO_BASE_URL>/api/auth/callback`。
- `LOGTO_BASE_URL` 是否与浏览器实际访问地址一致。
- `LOGTO_COOKIE_SECRET` 是否至少 32 个字符。
- 用户是否真的拥有已验证邮箱。
- 本地是否已经存在同邮箱或同 `logtoSub` 的用户，以及该用户是否被禁用。
