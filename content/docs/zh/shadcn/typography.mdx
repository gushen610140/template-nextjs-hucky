shadcn 组件不声明字体族。打开 `components/ui/button.tsx` 只会看到 `text-xs font-semibold tracking-widest uppercase` 这类排版参数（字号、字重、字距、大小写），没有一个 `font-family`。字体靠 CSS 继承从根元素传下来，所以整个项目只需要在 `<html>` 上决定一次。

## 分工

| token | 系统兜底 | 可切换成 | 用在哪 |
| --- | --- | --- | --- |
| `--font-sans` | 无衬线，微软雅黑排位靠前 | 任何登记到 `sans` 的字体 | 全局默认，所有组件继承 |
| `--font-heading` | 衬线（宋体系） | 任何登记到 `heading` 的字体 | 组件显式写 `font-heading`（`CardTitle`、`SheetTitle` 等），以及 Fumadocs 文档页标题和 MDX 标题 |
| `--font-mono` | 等宽 | 任何登记到 `mono` 的字体 | `font-mono`、代码块 |

默认不加载任何 webfont。三个角色各自只有「系统默认 + 最多一个自定义字体」，同时最多存在三个自定义字体。

自定义字体不再区分中英文：一份字体文件同时接管中文和拉丁字形。中文 webfont 通常自带一套拉丁字形，所以字体栈只有两层：

```text
"Hucky <字体 id>"  →  var(--font-system-<角色>)
```

## 完整链路

1. **CSS 定义兜底栈。** `app/[locale]/globals.css` 的 `:root` 提供三组 `--font-system-*` 和对应的 `--app-font-*`：

   ```css
   --app-font-sans: var(--font-custom-sans, var(--font-system-sans));
   ```

   `--font-custom-*` 由运行时写入；没有它时整条声明直接落到系统兜底栈。

2. **映射成 Tailwind utility。** `@theme inline` 把 `--app-font-*` 映射成 `font-sans` / `font-mono` / `font-heading`。
3. **写到根元素。** `@layer base` 里的 `html { @apply font-sans }` 是唯一一次真正设置 `font-family` 的地方。
4. **FontProvider 按需下载。** `providers/font-provider.tsx` 读取用户选择，从 Cache Storage 取字体；没有缓存时先弹下载弹窗，从 COS 拉取成功后再写 `--font-custom-*`。
5. **组件继承。** 组件只覆盖字号和字重，字体族继续继承，包括 Portal 到 `body` 的 Dialog、Popover、DropdownMenu。

## 字体存储

字体放在腾讯云 COS 私有桶里，桶名 `hucky-fonts-1301215062`，地域 `ap-shanghai`：

- 固定目录 `fonts/`，文件平铺，不建子目录；
- 扩展名统一 `.ttf`；
- 文件名去掉扩展名就是全局唯一的字体 id，例如 `fonts/SarasaGothicSC-Regular.ttf` → `SarasaGothicSC-Regular`。

浏览器不直接持有密钥。下载流程是：

1. 前端请求 `GET /api/fonts/[id]`；
2. `app/api/fonts/[id]/route.ts` 校验 id 是否在注册表里，再由 `lib/fonts/cos.ts` 用 `FONT_COS_SECRET_*` 生成 10 分钟有效的签名 URL，并顺带 `headObject` 返回字节数；
3. 浏览器直连 COS 下载，`fetch` 读取 stream 上报真实字节进度；
4. 下载完成后写入 Cache Storage（桶名 `hucky-fonts-v1`，key 是 `/__fonts/<id>.ttf`），再用 `FontFace(ArrayBuffer)` 注册到 `document.fonts`。

字体的 URL 每次都会变（签名参数不同），所以缓存 key 用稳定的文件名，而不是签名 URL。

## 缓存与状态提示

主题页和 Popover 面板的字体选项右侧有一个状态图标：

- 云朵下载：未缓存，点击后触发下载；
- 云朵勾选：已缓存，点击立即生效；
- 旋转图标：下载中，同时弹出进度弹窗。

弹窗按 `Content-Length` 显示百分比；拿不到长度时降级为不确定态。若下载失败，弹窗提示错误，界面继续使用系统字体。缓存被浏览器清掉后，下次访问会重新检查缓存，缺失的字体自动回落成「系统默认」。

## 新增字体

1. 把 `xxx.ttf` 上传到 COS 的 `fonts/` 目录，文件名就是 id；
2. 在 `lib/font-presets.ts` 的 `FONT_LIBRARY` 里登记 id 与字重；
3. 在 `FONT_OPTIONS` 对应角色里追加 id，可以同时出现在多个角色里；
4. 在 `messages/{en,zh}.json` 的 `ThemeCustomizer.fonts` 下补显示名。

不需要改 `layout.tsx`，也不需要改 `globals.css`。

## 环境变量与 CORS

服务端需要以下变量（见 `.env.example`）：

```dotenv
FONT_COS_SECRET_ID=
FONT_COS_SECRET_KEY=
FONT_COS_BUCKET=hucky-fonts-1301215062
FONT_COS_REGION=ap-shanghai
```

这与 `.github/workflows/deploy.yml` 里的 `COS_SECRET_ID` / `COS_BUCKET` 是**两套独立的桶和角色**，变量名加 `FONT_` 前缀就是为了避免串用。

私有桶需要给站点域名配置 CORS：

- 允许来源：站点域名（本地开发加上 `http://localhost:3000`）；
- 允许方法：`GET`、`HEAD`；
- 暴露响应头：`Content-Length`（缺失时进度条自动降级）。

## 常见问题

**切换字体后没有网络请求？**

说明该字体之前已经下载过，命中了 Cache Storage；或者你选的是「系统默认」。

**为什么中英文一起变了？**

设计如此。一个自定义字体同时承担中文和拉丁字形，不再有独立的 `cjk` 角色。

**标题为什么还是衬线？**

`heading` 的兜底栈是衬线体系；只有选择自定义 heading 字体后才会整体切换。

**下载很慢 / 失败？**

字体文件通常 10–25MB。失败时检查 `FONT_COS_*` 是否配置、桶内对象是否存在、以及桶的 CORS 是否放行站点域名。

**`var()` 为什么带第二个参数？**

`font-family: var(--a), var(--b)` 里任何一个变量未定义，整条声明在计算值阶段就失效。`var(--font-custom-sans, var(--font-system-sans))` 保证没有自定义字体时仍然有完整的系统字体栈。

**Dialog、Popover 里的字体对不上？**

Portal 渲染到 `body`，继承链是 `body → html`，只要字体写在 `<html>` 上就没问题。这也是字体必须放在根元素的原因。
