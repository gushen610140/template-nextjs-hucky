推荐部署到 Vercel。`package.json` 的 `vercel-build` 把数据库准备放在 `next build` 之前，所以一次自动部署会依次生成 Prisma Client、应用迁移、同步 RBAC seed，再构建 Next.js。

## 部署前准备

- PostgreSQL：生产库同时提供 pooled 连接串（应用运行时）和直连串（迁移 / seed）。
- Logto：生产应用，回调地址指向生产域名。
- RustFS：浏览器可达的 S3 API、私有 bucket，以及允许生产域名的 CORS。
- Vercel：项目已连接 Git 仓库。

<Callout type="warn" title="生产配置不要复用开发值">
`LOGTO_BASE_URL`、`LOGTO_COOKIE_SECRET`、数据库连接串和 `RUSTFS_*` 都依赖实际域名或生产环境。直接复制 `.env.development` 会让登录回调、会话 Cookie 或文件直传在生产失效。
</Callout>

## Vercel 项目设置

导入项目时 Framework Preset 选 Next.js，Root Directory 保持仓库根目录。

### Build Command

Vercel 的 Next.js 预设默认执行 `build` 脚本，也就是 `next build`。在 Project Settings → Build and Deployment → Build Command 启用 Override，改成：

```text
bun run vercel-build
```

只写 `next build` 或 `bun run build` 会跳过 Prisma Client 生成、数据库迁移和 seed，部署后应用可能直接报错。也可以在 `vercel.json` 中设置 `buildCommand`，但不要在项目设置和 `vercel.json` 两处重复配置。

Install Command 保持自动检测即可。Vercel 识别到 `bun.lock` 后会使用 Bun；需要手动指定时填 `bun ci`。Node.js 版本选 20 或更高。

### 环境变量

在 Project Settings → Environment Variables 中添加变量，作用域选 Production。Build 阶段也需要读取这些值，所以不要把数据库变量只放在运行时配置里。

| 变量 | 生产环境取值 |
| --- | --- |
| `DATABASE_URL` | 生产库的 pooled / 连接池地址，应用运行时使用 |
| `MIGRATE_DATABASE_URL` | 生产库的直连地址，`migrate deploy` 和 seed 使用；不能是 PgBouncer transaction 池 |
| `LOGTO_ENDPOINT` | 生产 Logto 租户地址 |
| `LOGTO_APP_ID` / `LOGTO_APP_SECRET` | 生产 Logto 应用；secret 仅服务端使用 |
| `LOGTO_BASE_URL` | `https://<生产域名>`，同时把 Logto 回调地址改成同一域名 |
| `LOGTO_COOKIE_SECRET` | 重新生成的随机值，至少 32 个字符 |
| `BOOTSTRAP_ADMIN_EMAILS` | 首次部署的管理员邮箱，逗号分隔 |
| `RUSTFS_ENDPOINT` | 浏览器可达的生产 S3 API 地址，不是 9001 控制台 |
| `RUSTFS_ACCESS_KEY` / `RUSTFS_SECRET_KEY` | 生产凭据，仅服务端使用 |
| `RUSTFS_BUCKET` | 生产私有 bucket，CORS 允许生产域名 |

<Callout type="warn" title="这些变量必须换成生产值">
`DATABASE_URL`、`MIGRATE_DATABASE_URL`、`LOGTO_BASE_URL`、`LOGTO_COOKIE_SECRET`、`LOGTO_*` 应用凭据、`RUSTFS_ENDPOINT`、`RUSTFS_BUCKET` 以及 RustFS 的 CORS 都应按生产环境重新配置。尤其不要保留 localhost、示例邮箱或开发密钥。`BOOTSTRAP_ADMIN_EMAILS` 也要填真实管理员邮箱。
</Callout>

Vercel 的 Production 构建会自动注入 `NODE_ENV=production`，不需要手动添加。修改环境变量后要重新部署才会生效。

## vercel-build 的执行顺序

```json
{
  "scripts": {
    "db:generate": "prisma generate",
    "db:seed": "prisma db seed",
    "db:setup": "prisma generate && prisma migrate deploy && prisma db seed",
    "vercel-build": "bun run db:setup && next build"
  }
}
```

`vercel-build` 等于 `bun run db:setup && next build`，其中 `db:setup` 展开为三步数据库准备。

<Steps>

<Step>
### 生成 Prisma Client

`prisma generate` 根据 `prisma/schema.prisma` 把客户端写到 `lib/generated/prisma`。该目录被 `.gitignore` 忽略，干净环境里必须先执行，否则 `next build` 会因为找不到生成的代码而失败。
</Step>

<Step>
### 应用迁移

`prisma migrate deploy` 只执行 `prisma/migrations` 中已提交的迁移，不会生成新迁移，也不会重置数据库。迁移失败时构建失败，Vercel 不会把新版本切到线上。连接串优先读取 `MIGRATE_DATABASE_URL`，未设置时回退到 `DATABASE_URL`。
</Step>

<Step>
### 同步 RBAC seed

`prisma db seed` 读取 `prisma.config.ts` 中的 `migrations.seed` 配置，执行 `bun prisma/seed.ts`。脚本用 `MIGRATE_DATABASE_URL ?? DATABASE_URL` 建立直连，在一个事务里 upsert 权限和内置的 `admin` / `user` 角色，并把内置角色的权限对齐到 `lib/permissions`。

seed 是幂等的：每次部署都会运行，但不会重复插入数据，也不会删除自定义角色或业务数据。

**`migrate deploy` 不会自动执行 seed**。如果部署流程只跑迁移，内置角色和权限表会是空的，权限校验会把后台锁死。
</Step>

<Step>
### 构建 Next.js

`next build` 最后执行。此时 schema 已迁移、客户端已生成、RBAC 数据已就绪，构建产物可以直接上线。
</Step>

</Steps>

<Callout title="本地 build 不会做这些">
`bun run build` 只执行 `next build`。数据库准备只存在于 `vercel-build` 和 `db:setup` 中，所以 Vercel 的 Build Command 必须指向 `vercel-build`。
</Callout>

## Preview 部署

Build Command 对所有部署生效，Preview 也会执行 `vercel-build`。要么给 Preview 配置独立数据库和独立环境变量，要么让 Preview 只生成客户端并构建，不执行迁移。

如果希望只在 Production 迁移，可以把 `vercel-build` 改成按 `VERCEL_ENV` 分支：Production 执行完整的 `db:setup`，Preview 至少保留 `prisma generate && next build`。不要把 Preview 的数据库步骤整个跳过，否则预览构建会缺少生成的 Prisma Client。

<Callout type="error" title="不要让 Preview 连接生产库">
Preview 每次提交都会触发构建。如果 Preview 共享生产 `MIGRATE_DATABASE_URL`，每次推送都会对生产库执行迁移和 seed。
</Callout>

## 首次部署

1. 备份生产数据库。
2. 推送到 Vercel 的生产分支，确认构建日志按 `prisma generate` → `migrate deploy` → `RBAC seed completed.` → `next build` 的顺序成功。
3. 用 `BOOTSTRAP_ADMIN_EMAILS` 中的邮箱登录，确认获得 `admin` 角色。系统存在管理员后该变量失效。
4. 检查 Logto 回调和文件上传、下载；这些功能依赖生产域名和生产 RustFS CORS。
5. 在本地连接生产库运行 `bunx prisma migrate status`，确认没有待应用迁移。

## 常见失败

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 构建报找不到 Prisma Client | Build Command 仍是 `next build` | 改成 `bun run vercel-build` |
| 连接数据库超时 | Vercel 构建环境访问不到数据库，或连接串错误 | 检查数据库网络白名单、SSL 参数和 `MIGRATE_DATABASE_URL` |
| 迁移报 P3009 | 生产库存在失败迁移 | 先备份，修复后用 `migrate resolve` 标记；不要在生产运行 `migrate reset` |
| 登录后没有权限 | seed 未执行，或邮箱不在 `BOOTSTRAP_ADMIN_EMAILS` | 确认日志有 `RBAC seed completed.`，并核对邮箱 |
| 上传或下载失败 | `RUSTFS_ENDPOINT` 浏览器不可达，或 CORS 没有生产域名 | 改成公网 S3 地址，并补上 `PUT`、`GET`、`HEAD` 的 CORS |
