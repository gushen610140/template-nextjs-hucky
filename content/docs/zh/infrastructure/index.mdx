基础设施决定项目能否在每台机器和 CI 上得到一致结果。本目录记录两条最容易出问题的约定：

| 主题 | 内容 |
| --- | --- |
| [包管理工具](./package-manager) | 只使用 Bun，提交 `bun.lock`，用 `bun ci` 安装 |
| [环境变量](./environment-variables) | `.env.<NODE_ENV>` 与 `.env.example` 的区别，以及必填变量 |
| [格式化](./formatting) | 使用 Biome 与 VSCode 插件在保存时自动格式化 |
| [主题配置](./theme) | 用 Popover 调整基础色、主色、圆角和阴影 |

## 约定速览

- 包管理器：Bun。不要用 npm、pnpm 或 yarn 安装依赖。
- 锁文件：只提交 `bun.lock`。
- 安装：全新环境或 CI 使用 `bun ci`；日常增删依赖后用 `bun install` 更新锁文件。
- 真实环境变量：`.env.development`、`.env.production` 等只留在本地，不提交。
- 示例文件：`.env.example` 会提交，只放变量名和空值。

<Callout type="warn" title="这些是仓库约定，不是可选项">
混用包管理器会让本地和 CI 解析出不同的依赖树；把真实环境变量提交到 Git 则会直接泄露密钥。两种情况都会让排查成本远高于遵循约定。
</Callout>
