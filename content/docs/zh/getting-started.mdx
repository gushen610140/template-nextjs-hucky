## 环境要求

- Node.js 20 或更高版本
- Bun 1.2 或更高版本（`bun.lock` 使用文本格式）
- 一个 PostgreSQL 数据库
- 一个 Logto 应用（本地开发也需要）
- 一个 RustFS（S3 兼容）实例、私有 bucket，以及配置好的 CORS

## 安装

<Steps>

<Step>
### 安装依赖

```bash
bun ci
```

`bun ci` 会严格按 `bun.lock` 安装，不会改写锁文件；如果锁文件与 `package.json` 不同步，安装会直接失败。

</Step>

<Step>
### 配置环境变量

项目按 `NODE_ENV` 读取 `.env.<NODE_ENV>`，本地开发对应 `.env.development`。先从示例文件复制：

```bash
cp .env.example .env.development
```

Windows PowerShell：

```powershell
Copy-Item .env.example .env.development
```

然后填写数据库与 Logto 的真实值：

```ini
DATABASE_URL=postgresql://user:password@localhost:5432/hucky
# 本地开发可以填同一个地址
MIGRATE_DATABASE_URL=postgresql://user:password@localhost:5432/hucky

LOGTO_ENDPOINT=https://your-tenant.logto.app
LOGTO_APP_ID=your-app-id
LOGTO_APP_SECRET=your-app-secret
LOGTO_BASE_URL=http://localhost:3000
LOGTO_COOKIE_SECRET=a-long-random-string
BOOTSTRAP_ADMIN_EMAILS=you@example.com

# RustFS（S3 兼容对象存储）
RUSTFS_ENDPOINT=https://s3.example.com
RUSTFS_ACCESS_KEY=your-access-key
RUSTFS_SECRET_KEY=your-secret-key
RUSTFS_BUCKET=your-bucket
```

`DATABASE_URL` 是应用运行时使用的连接串；生产环境应使用托管数据库的 pooled / 连接池地址。`MIGRATE_DATABASE_URL` 只用于迁移、seed 和 Prisma Studio，必须是直连地址；本地开发两者可以填同一个值。

`LOGTO_BASE_URL` 是应用自身的地址，Logto 回调会回到这里；`LOGTO_COOKIE_SECRET` 至少 32 个字符，生产环境务必换成足够随机的值。`.env.example` 会提交到 Git，真实的 `.env*` 文件不会；完整说明见[环境变量](./infrastructure/environment-variables)。

`BOOTSTRAP_ADMIN_EMAILS` 用于首次部署：系统里还没有任何管理员时，这些邮箱登录后会自动获得 `admin` 角色。一旦存在管理员，该变量自动失效，可以保留也可以删除。

`RUSTFS_*` 是文件功能的前置条件：`RUSTFS_ENDPOINT` 必须是浏览器能直接访问的 S3 API 地址（通常 9000 端口，不是 9001 控制台），bucket 需要是私有的，并允许 `PUT`、`GET`、`HEAD` 的 CORS。区域固定 `us-east-1`，不通过环境变量配置。详见[文件存储](./files)。

</Step>

<Step>
### 初始化数据库

```bash
bunx prisma generate
bun run db:setup
```

`prisma generate` 生成客户端到 `lib/generated/prisma`。`db:setup` 会先生成客户端，再执行 `prisma migrate deploy` 应用迁移，最后运行幂等的 RBAC seed，创建内置角色和权限。开发新的迁移时仍使用 `bunx prisma migrate dev`。需要图形化查看数据时运行 `bunx prisma studio`。数据库结构、PostgreSQL 配置和迁移流程见 [Prisma 数据库](./prisma)。

</Step>

<Step>
### 启动开发服务器

```bash
bun dev
```

打开 `http://localhost:3000`，会被重定向到默认语言 `/zh`。

</Step>

</Steps>

## 常用脚本

| 命令 | 作用 |
| --- | --- |
| `bun ci` | 按 `bun.lock` 安装依赖（CI / 全新环境） |
| `bun install` | 安装依赖并更新 `bun.lock` |
| `bun dev` | 启动开发服务器 |
| `bun run build` | 生产构建 |
| `bun start` | 运行生产构建 |
| `bun run lint` | Biome 检查 |
| `bun run format` | Biome 格式化 |
| `bun run db:setup` | 生成客户端、应用迁移并同步 RBAC 种子数据 |
| `bun run db:seed` | 只同步 RBAC 种子数据（幂等） |

## 认证与路由保护

`proxy.ts` 做了两件事：先用 next-intl 补全语言前缀，再校验本地 Session Cookie。

- 公开路由：`/`、`/login`、`/docs`
- 其余路由未登录时会跳转到 `/<locale>/login?next=<原路径>`

新增公开页面时，记得同步修改 `proxy.ts` 里的 `publicRoutes`，否则会被拦截到登录页。

<Callout type="warn" title="新增文档页不需要改路由">
`/docs` 已加入公开路由，`content/docs` 下新增的页面会自动可访问。但如果你把文档挂到别的路径，需要重新评估 `publicRoutes`。
</Callout>
