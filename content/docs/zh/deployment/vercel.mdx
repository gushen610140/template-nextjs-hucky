Vercel 是默认托管方案：项目连接 Git 仓库后，每次推送自动构建、迁移并发布，不需要维护服务器。生产环境变量见 [部署概览](/zh/docs/deployment#环境变量)。

## 项目设置

导入项目时 Framework Preset 选 Next.js，Root Directory 保持仓库根目录。

### Build Command

Vercel 的 Next.js 预设默认执行 `build` 脚本，也就是 `next build`。在 Project Settings → Build and Deployment → Build Command 启用 Override，改成：

```text
bun run vercel-build
```

只写 `next build` 或 `bun run build` 会跳过 Prisma Client 生成、数据库迁移和 seed，部署后应用可能直接报错。也可以在 `vercel.json` 中设置 `buildCommand`，但不要在项目设置和 `vercel.json` 两处重复配置。

Install Command 保持自动检测即可。Vercel 识别到 `bun.lock` 后会使用 Bun；需要手动指定时填 `bun ci`。Node.js 版本选 22：Next.js 16 要求 20.9 以上，22 是当前 LTS，Vercel 的构建镜像与运行时都默认提供。

Next.js 16 在 Vercel 上默认使用 Turbopack 构建，`next.config.ts` 不再需要为构建内存额外调参。如果你把构建迁到内存更小的平台，再单独评估是否需要限制 worker 数量。

### 环境变量

在 Project Settings → Environment Variables 中添加变量，作用域选 Production。Vercel 的 Production 构建和运行时共用同一份变量：Build 阶段会真实连接数据库、执行迁移和 seed，因此这些值必须直接填生产值，不能放占位符。

完整变量表见 [部署概览](/zh/docs/deployment#环境变量)。Vercel 的 Production 构建会自动注入 `NODE_ENV=production`，不需要手动添加。环境变量只在部署或重新部署时读取，修改后必须触发一次新部署才会生效。

## vercel-build 的执行顺序

`vercel-build` 等于 `bun run db:setup && next build`。日志应按以下顺序出现：

1. `prisma generate`
2. `prisma migrate deploy`
3. `RBAC seed completed.`
4. `next build`

每一步的行为见 [部署概览](/zh/docs/deployment#构建脚本)。

## Preview 部署

Build Command 对所有部署生效，Preview 也会执行 `vercel-build`。要么给 Preview 配置独立数据库和独立环境变量，要么让 Preview 只生成客户端并构建，不执行迁移。注意环境变量的作用域是分开的：只给 Production 配了变量时，Preview 构建读不到，会直接失败。

如果希望只在 Production 迁移，可以把 `vercel-build` 改成按 `VERCEL_ENV` 分支：Production 执行完整的 `db:setup`，Preview 至少保留 `prisma generate && next build`。不要把 Preview 的数据库步骤整个跳过，否则预览构建会缺少生成的 Prisma Client。

<Callout type="error" title="不要让 Preview 连接生产库">
Preview 每次提交都会触发构建。如果 Preview 共享生产 `MIGRATE_DATABASE_URL`，每次推送都会对生产库执行迁移和 seed。
</Callout>

## 首次部署

1. 备份生产数据库。
2. 推送到 Vercel 的生产分支，确认构建日志按 `prisma generate` → `migrate deploy` → `RBAC seed completed.` → `next build` 的顺序成功。
3. 用 `BOOTSTRAP_ADMIN_EMAILS` 中的邮箱登录，确认获得 `admin` 角色。系统存在管理员后该变量失效。
4. 检查 Logto 回调和文件上传、下载；这些功能依赖生产域名和生产 RustFS CORS。
5. 按需验证 AI 供应商保存（`AI_SECRET_KEY`）、知识库检索（`QDRANT_*`）和文档编辑（`ONLYOFFICE_*`）。
6. 在本地连接生产库运行 `bunx prisma migrate status`，确认没有待应用迁移。

## 常见失败

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 构建报找不到 Prisma Client | Build Command 仍是 `next build` | 改成 `bun run vercel-build` |
| `datasource.url property is required` | `MIGRATE_DATABASE_URL` 存在但为空 | 删掉该行或填入与 `DATABASE_URL` 相同的值 |
| 连接数据库超时 | Vercel 构建环境访问不到数据库，或连接串错误 | 检查数据库网络白名单、SSL 参数和 `MIGRATE_DATABASE_URL` |
| 迁移报 P3009 | 生产库存在失败迁移 | 先备份，修复后用 `migrate resolve` 标记；不要在生产运行 `migrate reset` |
| 登录后没有权限 | seed 未执行，或邮箱不在 `BOOTSTRAP_ADMIN_EMAILS` | 确认日志有 `RBAC seed completed.`，并核对邮箱 |
| 上传或下载失败 | `RUSTFS_ENDPOINT` 浏览器不可达，或 CORS 没有生产域名 | 改成公网 S3 地址，并补上 `PUT`、`GET`、`HEAD` 的 CORS |
| 登录回调报 redirect_uri 不匹配 | Logto 控制台登记的地址与实际域名不一致 | 必须精确填 `<LOGTO_BASE_URL>/api/auth/callback`，协议和结尾斜杠都要一致 |
| 文档编辑页提示缺少配置 | `ONLYOFFICE_DS_URL` 或 `ONLYOFFICE_JWT_SECRET` 未配置 / JWT 不一致 | 补全变量，并确保与 Document Server 的 `JWT_SECRET` 完全相同 |
| 保存文档无反应 | `ONLYOFFICE_SAVE_CALLBACK_URL` 缺失或指向 loopback | 填生产域名，代码会自动补 `/api/onlyoffice/callback` |
| AI 供应商保存失败 | `AI_SECRET_KEY` 缺失，或部署后更换过 | 恢复原值；更换后旧密文无法解密 |
| RAG 索引 / 检索报错 | `QDRANT_*` 缺失或 `QDRANT_VECTOR_SIZE` 与模型不一致 | 补全变量；维度必须与 embedding 模型输出一致，集合建好后不能改 |
| 改了变量但线上行为没变 | Vercel 只在部署时读取变量 | 触发一次新的 Production 部署 |
