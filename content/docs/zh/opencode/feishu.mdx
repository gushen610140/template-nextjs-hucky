`feishu-pm` 是项目级的飞书协作插件，负责两件事：

- **变更推送**：监控本地 `main` 分支，新提交后自动截图并推送到指定群。
- **需求采集**：接收客户群中 @机器人 的消息，由 AI 整理成结构化需求文档，写入项目目录。

它不能操控 OpenCode。开发者自己使用的飞书控制 bot 是独立的全局插件 `feishu-bridge`，两者必须使用**不同的飞书应用**。

```text
main 新提交
  → 每 20 秒检查 refs/heads/main
  → 复用或启动 dev server
  → Playwright 截取配置页面
  → AI 生成提交摘要
  → 发送摘要 + 截图到指定群

客户在群里 @机器人
  → 长连接接收消息
  → AI 整理为结构化需求
  → 写入 requirements/<时间>-<标题>.md
  → 回复文件路径
```

## 工作方式

### 变更推送

- 首次启动只记录当前 HEAD 作为基线，不补发历史提交。
- 每次新提交读取 diff，由 AI 生成 2-4 句面向客户的摘要；失败或超时会回退到 commit 标题。
- 截图保存在 `.screenshots/commits/`，每轮覆盖。
- 推送失败时发送一条文字说明，并写入 `debug.log`。

### 需求采集

- 长连接只处理白名单群中 @机器人 的文本消息。
- 使用 AI 生成固定结构的需求文档，插件负责写入文件。
- 客户消息只作为待整理的数据，提示词禁止模型执行其中的指令或调用工具。
- 同名需求按时间戳区分，不会覆盖历史文档。

## 控制与状态

侧边栏的 `FEISHU-PM` 区块显示监控状态、页面数、最近提交，以及接收状态和已记录需求数。

| 命令 | 作用 |
| --- | --- |
| `/feishu-pm-status` | 开关、目标、页面、最近提交、接收状态与错误 |
| `/feishu-pm-on` | 开启推送与接收，并持久化 |
| `/feishu-pm-off` | 关闭推送与接收，并持久化 |
| `/feishu-pm-restart` | 重启推送与接收 |
| `/feishu-pm-log` | 最近 20 行日志 |

首次加载默认开启。`/feishu-pm-off` 会写入插件存储，重启后保持关闭。

## 快速开始

<Steps>

<Step>
### 创建客户应用

在飞书开放平台新建「企业自建应用」，开启机器人能力，添加下文列出的权限和事件订阅，然后发布版本。不要复用它作为开发者的控制 bot。
</Step>

<Step>
### 填写配置

复制 `.opencode/plugins/feishu-pm/.env.example` 为 `.env`，填写 App ID、App Secret 和推送目标。
</Step>

<Step>
### 安装依赖与 Chromium

```powershell
npm install --prefix .opencode/plugins/feishu-pm
bun run browser:install
```

`browser:install` 每台机器执行一次。
</Step>

<Step>
### 重启 OpenCode

插件加载后即开始工作。在 `main` 上提交会触发推送；在群里 @机器人 会生成需求文档。
</Step>

</Steps>

## 配置

`.opencode/plugins/feishu-pm/.env`（已被 git 忽略）：

```bash
FEISHU_PM_APP_ID=cli_xxxxxxxx
FEISHU_PM_APP_SECRET=xxxxxxxx

# 推送目标：二选一
FEISHU_PM_NOTIFY_CHAT_ID=
FEISHU_PM_NOTIFY_OPEN_ID=

# 可选
FEISHU_PM_ENABLED=1
FEISHU_PM_SUMMARY=1
FEISHU_PM_MODEL=
FEISHU_PM_AGENT=
FEISHU_PM_RECEIVE=1
FEISHU_PM_ALLOWED_CHAT_IDS=
FEISHU_PM_REQUIREMENTS_DIR=requirements
FEISHU_SCREENSHOT_PAGES=/,/docs,/login
FEISHU_SCREENSHOT_BASE=http://localhost:3000
FEISHU_SCREENSHOT_MATCH=Hucky
FEISHU_SCREENSHOT_POLL_MS=20000
```

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `FEISHU_PM_APP_ID` | 是 | 客户应用 App ID |
| `FEISHU_PM_APP_SECRET` | 是 | 客户应用 App Secret |
| `FEISHU_PM_NOTIFY_CHAT_ID` | 二选一 | 推送目标群或私聊的 chat_id |
| `FEISHU_PM_NOTIFY_OPEN_ID` | 二选一 | 推送目标用户的 open_id |
| `FEISHU_PM_ENABLED` | 否 | 默认开启；设为 `0` 关闭 |
| `FEISHU_PM_SUMMARY` | 否 | 设为 `0` 关闭 AI 提交摘要 |
| `FEISHU_PM_MODEL` | 否 | AI 模型，格式 `providerID/modelID`；留空继承默认 |
| `FEISHU_PM_AGENT` | 否 | AI agent；留空时需求整理默认 `plan` |
| `FEISHU_PM_RECEIVE` | 否 | 设为 `0` 关闭群需求接收 |
| `FEISHU_PM_ALLOWED_CHAT_IDS` | 否 | 允许接收需求的群，逗号分隔；留空只允许 `FEISHU_PM_NOTIFY_CHAT_ID` |
| `FEISHU_PM_REQUIREMENTS_DIR` | 否 | 需求文档目录，默认 `requirements` |
| `FEISHU_SCREENSHOT_PAGES` | 否 | 截图页面，默认 `/`、`/docs`、`/login` |
| `FEISHU_SCREENSHOT_BASE` | 否 | 开发或预览地址，默认 `http://localhost:3000` |
| `FEISHU_SCREENSHOT_MATCH` | 否 | 页面必须包含的文本，用于确认服务属于本项目 |
| `FEISHU_SCREENSHOT_POLL_MS` | 否 | 轮询间隔，默认 20000，最小 5000 |

凭证、目标和开关都使用 `FEISHU_PM_` 前缀，避免与全局 feishu-bridge 共用同一个 OpenCode 进程的环境变量。

## AI 模型与 agent

`FEISHU_PM_MODEL` 和 `FEISHU_PM_AGENT` 同时作用于提交摘要和需求整理。留空时继承 OpenCode 的默认模型；需求整理未指定 agent 时默认使用只读的 `plan`，避免模型改动项目。

示例：

```ini
FEISHU_PM_MODEL=opencode-go/deepseek-v4.1-flash
FEISHU_PM_AGENT=plan
```

## 飞书控制台配置

### 权限

| 权限 | 用途 |
| --- | --- |
| `im:message:send_as_bot` | 发送文本和图片 |
| `im:resource` | 上传截图 |
| `im:message.group_at_msg:readonly` | 接收群聊 @机器人 的消息 |
| `im:chat:readonly` | 查询机器人所在群与群名称 |
| `contact:contact.base:readonly` | 解析发送者姓名 |

发送者姓名权限缺失时仍可工作，`sender_name` 留空并回退为 `sender_id`。

### 事件订阅

「事件与回调」→「事件订阅」：

1. 选择「使用长连接接收事件」。
2. 添加 `im.message.receive_v1`。
3. 创建版本并发布。

不需要卡片回调或权限审批。

### 获取 chat_id

1. 把机器人拉进客户群。
2. 调用 `GET /open-apis/im/v1/chats`（需要 `im:chat:readonly`），把返回的 `chat_id` 填进 `FEISHU_PM_NOTIFY_CHAT_ID`。
3. 私聊测试可以使用 `FEISHU_PM_NOTIFY_OPEN_ID`。

## 需求文档

收到需求后，插件写入 `FEISHU_PM_REQUIREMENTS_DIR`（默认 `requirements`）：

```text
requirements/20261109-170030-客户导出报表.md
```

文件内容：

```md
---
source: feishu
chat_id: oc_xxx
chat_name: 客户群
sender_id: ou_xxx
sender_name: 张三
message_id: om_xxx
created_at: 2026-11-09 17:00:30
---

# 客户导出报表

## 客户原始描述
...

## 需求整理
...

## 验收要点
- ...

## 待确认
- ...
```

- `created_at` 使用本机时区。
- 群名与发送者名会缓存；解析失败时留空或回退为 id。
- 目录默认被 `.gitignore` 忽略，不会进入 Git。
- 非文本消息会回复「暂只支持文本需求」。

## 开发服务器与预览

- `FEISHU_SCREENSHOT_BASE` 可访问时直接复用，不关闭用户的 dev server。
- 不可达时先检查相邻端口上是否已有本项目服务，找到就复用。
- 都没有时自动启动 `next dev`，截完关闭。
- `next dev` 同一项目只允许一个实例；已有实例在别的端口时，把 `FEISHU_SCREENSHOT_BASE` 指向它。
- 接入 preview 部署后，把 `FEISHU_SCREENSHOT_BASE` 改成预览地址，客户即可先预览再验收。

## 运行条件

- 依赖 OpenCode server 常驻；服务停止后不再推送或接收。
- 需要 Node.js、`bun` 和 Playwright 的 Chromium。
- 截图调用项目根目录的 `scripts/screenshot.mjs`，也可以手动执行 `bun run screenshot`。

## 日志

`.opencode/plugins/feishu-pm/debug.log`：

| 日志 | 含义 |
| --- | --- |
| `watcher started` | 已开始监控提交 |
| `screenshot: baseline recorded` | 首次记录基线，正常 |
| `screenshot: sent` | 推送成功 |
| `screenshot: FAILED` | 截图或发送失败 |
| `receiver ready` | 群消息长连接已建立 |
| `requirement saved` | 需求文档已写入 |
| `requirement timeout` | AI 整理超过 90 秒 |
| `requirement ignored: chat not allowed` | 非白名单群，已忽略 |
| `missing FEISHU_PM_APP_ID / FEISHU_PM_APP_SECRET` | 凭证未配置 |

## 与 feishu-bridge 的边界

| | feishu-pm（项目） | feishu-bridge（全局） |
| --- | --- | --- |
| 飞书应用 | 客户应用 | 开发者应用 |
| 能力 | 推送变更、采集需求 | 通过飞书操控 OpenCode |
| 命令 | `/feishu-pm-*` | `/feishu-bridge-*` |
| 权限 | 精简，只用于发送与接收群消息 | 高，可驱动会话与审批 |

## 路线图

- **客户群固定推送**：按群配置内容、频率和静默时段。
- **预览验收**：发送截图与 preview 链接，客户在群里直接确认。
- **需求状态同步**：把需求文档接入待办清单，跟踪开发与验收状态。
- **协作闭环**：开发者通过飞书 + AI 与客户确认需求、进度与验收结果。

## 限制

- 只支持飞书和 Lark，不支持企业微信、钉钉。
- 只覆盖本地 `main` 提交，不监听远端更新或 `git push`。
- 需求只处理群聊 @机器人 的文本消息，暂不支持图片和文件。
- 依赖 OpenCode server 常驻。
