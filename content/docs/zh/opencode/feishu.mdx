`feishu-pm` 是一个项目级 OpenCode 插件，用来把最近的代码变更推送给客户或团队：监控本地 `main` 分支，发现新提交后自动截取页面，发送提交摘要和截图。

它只发送消息，不接收命令，也不能操控 OpenCode。开发者自己使用的飞书控制 bot 是独立的全局插件 `feishu-bridge`，两者必须使用**不同的飞书应用**。

```text
main 新提交
  → 每 20 秒检查一次 refs/heads/main
  → 复用或启动 dev server
  → Playwright 截取配置页面
  → 提交摘要 + 截图
  → 指定飞书群 / 私聊
```

## 工作方式

- 首次启动只记录当前 HEAD 作为基线，不补发历史提交。
- 每次新提交会用 OpenCode 的 AI 阅读 diff，生成 2-4 句面向客户的变更摘要；生成失败或超时会回退到 commit 标题。
- 截图保存在 `.screenshots/commits/`，每轮覆盖。
- 推送失败时发送一条文字说明，并写入 `debug.log`。
- 不建立飞书长连接，不需要事件订阅或卡片回调，OpenCode server 运行即生效。

## 控制与状态

侧边栏的 `FEISHU-PM` 区块显示 `watching` / `off`、页面数量和最近提交。TUI 命令：

| 命令 | 作用 |
| --- | --- |
| `/feishu-pm-status` | 开关、目标、页面、最近提交与错误 |
| `/feishu-pm-on` | 开启并持久化 |
| `/feishu-pm-off` | 关闭并持久化 |
| `/feishu-pm-restart` | 重启监控 |
| `/feishu-pm-log` | 最近 20 行日志 |

首次加载默认开启。`/feishu-pm-off` 会写入插件存储，重启后保持关闭。

开发者控制 bot 是独立的全局插件，命令前缀为 `/feishu-bridge-*`。

## 快速开始

<Steps>

<Step>
### 创建客户应用

在飞书开放平台新建一个「企业自建应用」，开启机器人能力，只添加发送所需权限，然后发布版本。不要复用它作为开发者的控制 bot。

| 权限 | 用途 |
| --- | --- |
| `im:message:send_as_bot` | 发送文本和图片 |
| `im:resource` | 上传截图 |

</Step>

<Step>
### 填写配置

复制 `.opencode/plugins/feishu-pm/.env.example` 为 `.env`，填写 App ID、App Secret 和推送目标。`.env` 已被 git 忽略。
</Step>

<Step>
### 安装依赖与 Chromium

```powershell
npm install --prefix .opencode/plugins/feishu-pm
bun run browser:install
```

`browser:install` 每台机器执行一次。
</Step>

<Step>
### 重启 OpenCode

插件加载后即开始监控，不需要 `/feishu-on`。在 `main` 上提交一次改动，20 秒内应收到摘要和截图。

</Step>

</Steps>

## 配置

```bash
FEISHU_APP_ID=cli_xxxxxxxx
FEISHU_APP_SECRET=xxxxxxxx

# 推送目标：二选一
FEISHU_NOTIFY_CHAT_ID=
FEISHU_NOTIFY_OPEN_ID=

# 可选
FEISHU_PM_ENABLED=1
FEISHU_PM_SUMMARY=1
FEISHU_SCREENSHOT_PAGES=/,/docs,/login
FEISHU_SCREENSHOT_BASE=http://localhost:3000
FEISHU_SCREENSHOT_MATCH=Hucky
FEISHU_SCREENSHOT_POLL_MS=20000
```

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `FEISHU_APP_ID` | 是 | 客户应用 App ID |
| `FEISHU_APP_SECRET` | 是 | 客户应用 App Secret |
| `FEISHU_NOTIFY_CHAT_ID` | 二选一 | 群或私聊的 chat_id，优先使用 |
| `FEISHU_NOTIFY_OPEN_ID` | 二选一 | 私聊用户的 open_id |
| `FEISHU_PM_ENABLED` | 否 | 默认开启；设为 `0` 关闭 |
| `FEISHU_PM_SUMMARY` | 否 | 设为 `0` 关闭 AI 摘要 |
| `FEISHU_SCREENSHOT_PAGES` | 否 | 要截取的页面，默认 `/`、`/docs`、`/login` |
| `FEISHU_SCREENSHOT_BASE` | 否 | 开发或预览地址，默认 `http://localhost:3000` |
| `FEISHU_SCREENSHOT_MATCH` | 否 | 页面必须包含的文本，用于确认服务属于本项目 |
| `FEISHU_SCREENSHOT_POLL_MS` | 否 | 轮询间隔，默认 20000，最小 5000 |

目标只从配置读取，因此客户应用不需要接收消息的能力。

## 获取 chat_id

1. 把机器人拉进客户群。
2. 在飞书开放平台 API 调试台调用 `GET /open-apis/im/v1/chats`（需要 `im:chat:readonly`），把返回的 `chat_id` 填进 `FEISHU_NOTIFY_CHAT_ID`。
3. 只做私聊验证时，也可以先填 `FEISHU_NOTIFY_OPEN_ID`。

## 开发服务器与预览

- `FEISHU_SCREENSHOT_BASE` 可访问时直接复用，不关闭用户的 dev server。
- 不可达时先检查相邻端口上是否已有本项目服务，找到就复用。
- 都没有时自动启动 `next dev`，截完关闭。
- `next dev` 同一项目只允许一个实例；已有实例在别的端口时，把 `FEISHU_SCREENSHOT_BASE` 指向它。
- 接入 preview 部署后，把 `FEISHU_SCREENSHOT_BASE` 改成预览地址，客户即可先预览再验收。

## 运行条件

- 依赖 OpenCode server 常驻；服务停止后不再推送。
- 需要 Node.js、`bun` 和 Playwright 的 Chromium。
- 截图调用项目根目录的 `scripts/screenshot.mjs`，也可以手动执行 `bun run screenshot`。

## 日志

`.opencode/plugins/feishu-pm/debug.log`：

| 日志 | 含义 |
| --- | --- |
| `watcher started` | 已开始监控 |
| `screenshot: baseline recorded` | 首次记录基线，正常 |
| `screenshot: sent` | 推送成功 |
| `screenshot: no feishu target` | 发送目标缺失 |
| `screenshot: FAILED` | 截图或发送失败 |
| `dev server 启动失败` | 已有 `next dev` 实例或端口冲突 |
| `missing FEISHU_APP_ID / FEISHU_APP_SECRET` | 凭证未配置 |

## 路线图

- **客户群固定推送**：按群配置内容、频率和静默时段。
- **预览验收**：把截图与 preview 链接一起发送，客户直接在群里确认。
- **群消息整理**：监控客户反馈，由 AI 归纳为结构化需求，写入项目待办清单。
- **协作闭环**：开发者通过飞书 + AI 与客户确认需求、进度与验收结果。

这些能力尚未实现，文档会在落地后同步更新。

## 限制

- 只支持飞书和 Lark，不支持企业微信、钉钉。
- 只覆盖本地 `main` 提交，不监听远端更新或 `git push`。
- 推送目标必须预先配置，不支持按消息自动发现。
- 依赖 OpenCode server 常驻。
