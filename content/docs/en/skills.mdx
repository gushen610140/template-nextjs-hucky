Skills are reusable instruction packs for agents. This project captures repeatable workflows as skills so an agent can load them on demand instead of repeating the instructions in every prompt. For the recommended OpenCode workflow and worktrees, see [OpenCode](/en/docs/opencode).

## Why .agents is not committed

Like `node_modules`, skills are install artifacts, so **`.agents/` is not committed to Git**:

| Path | Committed | Purpose |
| --- | --- | --- |
| `.agents/skills/` | No, ignored by `.gitignore` | Installed skill files |
| `.opencode/skills/` | Yes | Project skills committed with the repo |
| `skills-lock.json` | Yes | Pins each skill's source and hash |
| `skills` in `package.json` | Yes | Provides the `skills` CLI |

A fresh clone therefore has no `.agents/skills/`; restore it from `skills-lock.json`. `.opencode/skills/` is different: it is committed to Git and OpenCode discovers it without any install step.

## Skills committed with the repo

Skills under `.opencode/skills/` bypass `skills-lock.json`. They are committed with the code and are available right after cloning.

### browser-screenshot

Captures any URL or local page with Playwright and Chromium for visual verification and layout checks. The browser binary is not part of the repo, so each machine downloads it once:

```bash
bun run browser:install
```

Then capture:

```bash
# Local page; base defaults to http://localhost:3000
bun run screenshot http://localhost:3000 --out .screenshots/home.png

# Any URL, full page
bun run screenshot https://example.com --full-page

# One element, mobile viewport
bun run screenshot /docs --selector "main" --viewport 390x844
```

The script prints JSON with the absolute path, HTTP status, and page size. Images go to `.screenshots/` by default, which is gitignored. Common options: `--full-page`, `--selector`, `--viewport WxH`, `--wait-for`, `--wait-until`, `--color-scheme`, `--scale`.

`playwright` is a dev dependency only and never reaches the production build; `bun ci` does not download Chromium. Start `bun dev` before capturing local pages.

## Using grill-me for complex problems

`grill-me` is an interview-style skill: instead of producing a plan immediately, it questions assumptions, constraints, and edge cases until the design is sharp. Invoke it for architecture decisions, cross-module refactors, and ambiguous requirements. Skip it for small, well-defined changes.

```text
Use the grill-me skill to challenge this design before implementation.
```

The project's `AGENTS.md` asks the agent to invoke this skill for complex tasks.

## Installing skills (optional)

This step only controls which skill packs the agent can use. Skipping it does not affect starting or building the app. Skills under `.opencode/skills/` are committed with the repo; only the 12 packs in `skills-lock.json` need restoring.

The skills CLI requires Node.js 22.20 or newer. This project already lists `skills` in `devDependencies`, so install dependencies first, then restore from the lock file:

<Steps>

<Step>
### Install project dependencies

```bash
bun ci
```

</Step>

<Step>
### Restore skills from the lock file

```bash
bunx skills experimental_install
```

This reads `skills-lock.json` and restores skills into `.agents/skills/`. It does not install npm packages, so run it after `bun ci`.

</Step>

<Step>
### Verify the installation

```bash
bunx skills list
```

You should see the 12 skills listed above. OpenCode loads `.agents/skills/` automatically; no extra copying is required.

</Step>

</Steps>

`experimental_install` is still experimental. If the command is renamed or unavailable in the future, install by source instead:

```bash
bunx skills add prisma/skills --skill '*' -a opencode -y
bunx skills add shadcn/ui --skill shadcn -a opencode -y
bunx skills add juliusbrussee/caveman --skill caveman-commit -a opencode -y
bunx skills add mattpocock/skills --skill grill-me -a opencode -y
```

## Updates and maintenance

Only run `add` / `update` when you intentionally change the skill set. Those commands rewrite `skills-lock.json`; commit the lock file with your changes, but do not commit `.agents/`, which is an install directory that can be rebuilt at any time.

Other agents can reuse these skills too, but OpenCode is the recommended agent for this project. See [OpenCode](/en/docs/opencode) for the workflow.
