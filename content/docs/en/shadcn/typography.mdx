shadcn components never declare a font family. Open `components/ui/button.tsx` and you only find typographic parameters such as `text-xs font-semibold tracking-widest uppercase` — font size, weight, letter spacing, casing — and not a single `font-family`. Fonts arrive by CSS inheritance from the root element, so the whole project only needs to decide once, on `<html>`.

## Responsibilities

| token | Latin glyphs | Chinese glyphs | Used by |
| --- | --- | --- | --- |
| `--font-sans` | System sans; can switch to Neo Sans Pro / Eras | System sans stack; can switch to ZhouFang RiMing / LXGW WenKai | Global default, inherited by every component |
| `--font-heading` | System serif; can switch to DIN 1451 Mittelschrift | System serif stack | Components that opt in with `font-heading` (`CardTitle`, `SheetTitle`, ...), plus Fumadocs page titles and MDX headings |
| `--font-mono` | System mono; can switch to Noto Sans Mono | System mono stack | `font-mono`, code blocks |

No webfont is loaded by default. A font file is fetched through the `FontFace` API only after the user actively switches to it in the theme panel. Heading and code Chinese glyphs stay on the system stacks; only the body slot (`--font-cjk-sans`) can be swapped for a self-hosted face.

The Chinese face is a separate slot: it overrides `--font-cjk-sans` only, while Latin glyphs still come from `--font-latin-*`. The theme panel merges both into one Body option for simplicity, but the underlying layers remain independent.

## The full chain

1. **CSS defines the default stacks.** `:root` in `app/[locale]/globals.css` provides `--font-system-*`, `--font-system-cjk-*`, and the three `--app-font-*` tokens:

   ```css
   --app-font-sans:
     var(--font-latin-sans, var(--font-system-sans)), var(--font-system-cjk-sans);
   ```

   Without `--font-latin-*`, the Latin slot falls back to its system stack; Chinese defaults to `--font-system-cjk-*`. Selecting a Chinese webfont switches to the `:root[data-cjk-font]` variant described in the next section.

2. **Tailwind utilities are generated.** `@theme inline` maps `--app-font-*` to `font-sans` / `font-mono` / `font-heading`.
3. **The family is applied once.** `html { @apply font-sans }` inside `@layer base` is the only place that actually sets `font-family`.
4. **FontProvider loads on demand.** `providers/font-provider.tsx` reads the user's choice, loads files from `public/fonts/` with `FontFace`, and only then writes `--font-latin-*` (Latin) or `--font-cjk-sans` (Chinese body).
5. **Components inherit.** They override size and weight only. Inheritance also covers components portalled into `body` — Dialog, Popover, DropdownMenu.

Fumadocs body text reads `--font-sans` / `--font-mono`. Docs page titles and MDX headings are pointed at `--font-heading` by the `#nd-page :is(h1, h2, h3, h4, h5, h6)` rule at the end of `globals.css`, so switching the heading font updates them too.

## On-demand loading

The font registry lives in `lib/font-presets.ts`:

```ts
export const FONT_OPTIONS = {
  sans: ["system", "neosanspro", "erasmd"],
  heading: ["system", "din"],
  mono: ["system", "notosansmono"],
  cjk: ["system", "zhoufangriming", "lxgwwenkai"],
} as const;
```

Each local font records its family, file path, weight, and format. `FontProvider` behaves as follows:

- Every role defaults to `system`, which triggers no font request at all.
- Hovering or focusing a font option preloads it without applying it.
- On an actual switch it waits for `face.load()` before writing the CSS variable, avoiding a reflow caused by `font-display: swap`.
- The Chinese face additionally carries a `unicodeRange`, and the provider adds `data-cjk-font` to `<html>` to switch to the Chinese-first stack.
- The choice is stored in `localStorage` and restored on the next visit. Stored values are validated per role and missing roles fall back to their default, so settings saved by an older build keep working when a new role such as `cjk` is added.

`sans` / `heading` / `mono` control Latin glyphs; `cjk` controls Chinese body glyphs only. The two layers never interfere.

## Why Chinese still defaults to the system stack

A self-hosted Chinese face is optional; the default is still the system stack:

- **Size.** A complete Chinese font is easily 2MB or more. Even a common-character subset runs into hundreds of KB, a poor trade for the first paint.
- **On-demand loading helps less here.** Once enabled, a Chinese face is used everywhere in Chinese body text, unlike a heading face that only affects a few runs. Keeping it off by default is what guarantees a font-request-free first paint.
- **System faces are already tuned.** PingFang SC on macOS and Microsoft YaHei on Windows are adapted to their platforms for weight, spacing, and rendering.
- **The cost is cross-platform variance.** The same Chinese text looks different on macOS and Windows. Only if the design demands absolute consistency is a custom subset worth the trade.

The registered ZhouFang RiMing and LXGW WenKai faces exist for exactly that last case: they are loaded only when the user picks one, and nothing is requested otherwise. The files are about 8.6MB (OTF) and 24.4MB (TTF) respectively, both complete faces with no subsetting — see [Font source and license](#font-source-and-license).

## Why the Chinese face comes first but never touches English

"Latin first, Chinese second" is the intuitive order, but it does not work for a Chinese webfont.

On Chinese-locale Windows, `ui-sans-serif` / `system-ui` resolve to **Microsoft YaHei**, which covers both Chinese and Latin. It sits at the front of `--font-system-sans`, so any Chinese face placed after it can never be reached:

```text
ui-sans-serif (→ Microsoft YaHei, covers both)  ← grabs Chinese AND English
"Hucky ZhouFangRiMing"                          ← never used
```

So when a Chinese webfont is selected, `FontProvider` adds `data-cjk-font` to `<html>` and `globals.css` switches the stack:

```css
:root[data-cjk-font] {
  --app-font-sans:
    var(--font-cjk-sans),                             /* Chinese webfont, first */
    var(--font-latin-sans, var(--font-system-sans)),  /* English/digits */
    var(--font-system-cjk-sans);                      /* Chinese fallback */
}
```

It can sit first without touching English because of **`unicode-range`**: the face is registered for CJK code points only (`CJK_UNICODE_RANGE` in `lib/font-presets.ts`). Latin letters, digits, and code are outside that range, so the browser skips the face and moves on to the Latin stack.

Verified with Chrome DevTools Protocol `CSS.getPlatformFontsForNode`:

```text
Chinese "中文正文字体测试" → Sthginkra (isCustomFont: true)
English "Hamburgefonstiv"  → Microsoft YaHei (isCustomFont: false)
```

That is also why the Chinese face gets its own option instead of being folded into "Sans": the two layers are independent chains that can be combined freely.

## Adding a font

1. Put the font file under `public/fonts/`.
2. Register `family`, `file`, `weight`, and `format` in `FONT_LIBRARY` inside `lib/font-presets.ts`.
3. Add the id to the matching role in `FONT_OPTIONS`.
4. Add the display name under `ThemeCustomizer.fonts` in `messages/{en,zh}.json`.

No changes to `layout.tsx` or `globals.css` are needed. Adding a Chinese face works the same way: append the id to `FONT_OPTIONS.cjk`, but you **must** also set `unicodeRange: CJK_UNICODE_RANGE` in `FONT_LIBRARY`; otherwise the Latin glyphs bundled in the face take over English.

**Swap the Chinese fallback stack:** edit only `--font-system-cjk-*` under `:root`.

**Add a new font token** (say `--font-serif`) in three places:

1. `--app-font-serif` under `:root`;
2. `--font-serif: var(--app-font-serif)` inside `@theme inline`;
3. the role and CSS variable mapping in `lib/font-presets.ts`.

## Common questions

**`font-sans` in a component has no effect?**

Check Computed → `font-family` in DevTools first, then confirm `--font-latin-sans` exists on `<html>`. When it is absent the stack falls back to system fonts, which is expected.

**Why is there no network request after switching fonts?**

Either the font was already loaded, or you selected `system`. A request to `public/fonts/` only happens when a local face is selected and has not been loaded through `FontFace` yet.

**I picked a Chinese face but English did not change?**

That is by design. The face is registered with a `unicode-range` limited to CJK code points, so English and digits skip it and fall through to `--font-latin-sans` — even though the face sits first in the stack.

These Chinese faces do bundle Latin glyphs (ZhouFang RiMing from Iosevka; LXGW WenKai from Klee One), but they are unused in this configuration. To let a Chinese face take over English, remove `unicodeRange` from its `FONT_LIBRARY` entry — English, digits, and code all become that face's Latin glyphs, which is usually not what you want.

**Why is switching the Chinese face slow?**

ZhouFang RiMing is a full ~8.6MB OTF and LXGW WenKai a full ~24.4MB TTF, neither subsetted. They load on demand: the first selection (or hover/focus on the option) downloads one once, after which `document.fonts` and the browser cache take over. To improve first load, subset it to common characters with `fonttools` or `glyphhanger` and convert to woff2 at build time; the result is typically 1–2MB.

**Why does `var()` take two arguments?**

In `font-family: var(--a), var(--b)`, a single undefined variable invalidates the entire declaration at computed-value time. `var(--font-latin-sans, var(--font-system-sans))` guarantees a complete system stack when no webfont is selected.

**Dialog and Popover use the wrong font?**

Portals render into `body`, so the inheritance chain is `body → html`. Fonts on `<html>` survive; fonts scoped to a business `div` do not. That is exactly why the family belongs on the root element.

**Chinese headings look inconsistent with the Latin ones?**

The Latin heading face defaults to a system serif and can switch to DIN 1451; `--font-system-cjk-heading` prefers serif Chinese faces (Songti family). On Windows it lands on SimSun, which looks noticeably different from Songti on macOS — an inherent limit of system stacks.

**Does the Chinese face affect only body text?**

Yes. `--font-cjk-sans` is the only Chinese slot; headings and code keep `--font-system-cjk-heading` / `--font-system-cjk-mono`. To make headings switchable too, add a `cjkHeading` role to `FONT_ROLES` and map it to `--font-cjk-heading`.

**How do I change the Fumadocs heading font?**

Docs page titles and MDX headings use `--font-heading` through the `#nd-page :is(h1, h2, h3, h4, h5, h6)` rule at the end of `globals.css`. Switch the heading font option; no Fumadocs component changes are needed.
