title: Typography
description: System fonts by default, custom faces downloaded on demand from a private COS bucket and cached locally

shadcn components never declare a font family. Open `components/ui/button.tsx` and you only see typography parameters such as `text-xs font-semibold tracking-widest uppercase` — no `font-family`. Fonts are inherited from the root element, so the project decides once on `<html>`.

## Slots

| token | System fallback | Can switch to | Used by |
| --- | --- | --- | --- |
| `--font-sans` | Sans stack, Microsoft YaHei ranked high | Any font registered under `sans` | Global default, inherited everywhere |
| `--font-heading` | Serif stack (Songti family) | Any font registered under `heading` | Components with `font-heading` (`CardTitle`, `SheetTitle`, …) plus Fumadocs page and MDX headings |
| `--font-mono` | Monospace stack | Any font registered under `mono` | `font-mono`, code blocks |

No webfont is loaded by default. Each slot offers "system default" plus at most one custom face, so at most three custom faces exist at once.

A custom face covers Chinese and Latin glyphs together. CJK webfonts ship their own Latin set, so the stack only needs two layers:

```text
"Hucky <font id>"  →  var(--font-system-<slot>)
```

## Flow

1. **CSS defines the fallback.** `app/[locale]/globals.css` ships three `--font-system-*` stacks and the matching `--app-font-*` variables:

   ```css
   --app-font-sans: var(--font-custom-sans, var(--font-system-sans));
   ```

   `--font-custom-*` is written at runtime; without it the declaration resolves to the system stack.

2. **Mapping to Tailwind utilities.** `@theme inline` maps `--app-font-*` to `font-sans` / `font-mono` / `font-heading`.
3. **Writing to the root.** `html { @apply font-sans }` in `@layer base` is the only place a real `font-family` is set.
4. **FontProvider downloads on demand.** `providers/font-provider.tsx` reads the stored choice, looks it up in Cache Storage, and only writes `--font-custom-*` after the font is available locally.
5. **Inheritance everywhere.** Components override size and weight only; portals rendered into `body` keep the same font.

## Font storage

Fonts live in a private Tencent COS bucket, `hucky-fonts-1301215062` in `ap-shanghai`:

- fixed `fonts/` prefix, files flat, no nested folders;
- `.ttf` only;
- the filename without extension is the globally unique font id: `fonts/SarasaGothicSC-Regular.ttf` → `SarasaGothicSC-Regular`.

The browser never holds credentials:

1. The client calls `GET /api/fonts/[id]`.
2. `app/api/fonts/[id]/route.ts` validates the id against the registry, then `lib/fonts/cos.ts` signs a 10-minute URL with `FONT_COS_SECRET_*` and returns the object size from `headObject`.
3. The browser downloads straight from COS and reports real byte progress from the `fetch` stream.
4. On completion the file is stored in Cache Storage (`hucky-fonts-v1`, key `/__fonts/<id>.ttf`) and registered via `FontFace(ArrayBuffer)`.

Signed URLs change on every request, so the cache key is the stable filename rather than the URL.

## Cache and status hints

Each font option shows a status icon:

- cloud download — not cached, click to fetch;
- cloud check — cached, click applies instantly;
- spinner — downloading, with a progress dialog.

The dialog shows a percentage when `Content-Length` is available and falls back to indeterminate otherwise. Failures keep the system font active. If the browser evicts the cache, the slot resets to "system" on the next visit.

## Adding a font

1. Upload `xxx.ttf` to the COS `fonts/` prefix; the filename is the id;
2. Register the id and weight in `FONT_LIBRARY` (`lib/font-presets.ts`);
3. Append the id under the relevant `FONT_OPTIONS` slots — it may appear in several;
4. Add a display name under `ThemeCustomizer.fonts` in `messages/{en,zh}.json`.

`layout.tsx` and `globals.css` stay untouched.

## Environment and CORS

The server reads these variables (see `.env.example`):

```dotenv
FONT_COS_SECRET_ID=
FONT_COS_SECRET_KEY=
FONT_COS_BUCKET=hucky-fonts-1301215062
FONT_COS_REGION=ap-shanghai
```

They are deliberately separate from the deploy pipeline's `COS_SECRET_ID` / `COS_BUCKET`: different bucket, different role.

The private bucket needs CORS for the site origin:

- origins: your site plus `http://localhost:3000` for local dev;
- methods: `GET`, `HEAD`;
- exposed headers: `Content-Length` (progress falls back gracefully when missing).

## FAQ

**No network request after switching fonts?**

The file was already cached, or you picked "system default".

**Why do Chinese and Latin change together?**

By design. One custom face owns both scripts; there is no separate `cjk` slot.

**Why are headings still serif?**

The `heading` fallback is a serif stack. It only changes once a custom heading face is selected.

**Downloads fail or crawl?**

Fonts are typically 10–25MB. Check `FONT_COS_*`, that the object exists, and that bucket CORS allows the site origin.

**Why does `var()` take a second argument?**

`font-family: var(--a), var(--b)` becomes invalid at computed-value time if any variable is missing. `var(--font-custom-sans, var(--font-system-sans))` keeps a complete stack when no custom face is selected.
