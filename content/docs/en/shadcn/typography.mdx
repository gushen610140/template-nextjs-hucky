shadcn components never declare a font family. Open `components/ui/button.tsx` and you only find typographic parameters such as `text-xs font-semibold tracking-widest uppercase` — font size, weight, letter spacing, casing — and not a single `font-family`. Fonts arrive by CSS inheritance from the root element, so the whole project only needs to decide once, on `<html>`.

## Responsibilities

| token | Latin glyphs | Chinese glyphs | Used by |
| --- | --- | --- | --- |
| `--font-sans` | System sans; can switch to Neo Sans Pro / Eras | System sans stack | Global default, inherited by every component |
| `--font-heading` | System serif; can switch to DIN 1451 Mittelschrift | System serif stack | Components that opt in with `font-heading` (`CardTitle`, `SheetTitle`, ...), plus Fumadocs page titles and MDX headings |
| `--font-mono` | System mono; can switch to Noto Sans Mono | System mono stack | `font-mono`, code blocks |

No webfont is loaded by default. A font file is fetched through the `FontFace` API only after the user actively switches to it in the theme panel. Chinese glyphs always come from the system stack.

## The full chain

1. **CSS defines the default stacks.** `:root` in `app/[locale]/globals.css` provides `--font-system-*` and the three `--app-font-*` tokens:

   ```css
   --app-font-sans:
     var(--font-latin-sans, var(--font-system-sans)), var(--font-cjk-sans);
   ```

   Without `--font-latin-*`, the stack falls back to system fonts.

2. **Tailwind utilities are generated.** `@theme inline` maps `--app-font-*` to `font-sans` / `font-mono` / `font-heading`.
3. **The family is applied once.** `html { @apply font-sans }` inside `@layer base` is the only place that actually sets `font-family`.
4. **FontProvider loads on demand.** `providers/font-provider.tsx` reads the user's choice, loads files from `public/fonts/` with `FontFace`, and only then writes `--font-latin-*`.
5. **Components inherit.** They override size and weight only. Inheritance also covers components portalled into `body` — Dialog, Popover, DropdownMenu.

Fumadocs body text reads `--font-sans` / `--font-mono`. Docs page titles and MDX headings are pointed at `--font-heading` by the `#nd-page :is(h1, h2, h3, h4, h5, h6)` rule at the end of `globals.css`, so switching the heading font updates them too.

## On-demand loading

The font registry lives in `lib/font-presets.ts`:

```ts
export const FONT_OPTIONS = {
  sans: ["system", "neosanspro", "erasmd"],
  heading: ["system", "din"],
  mono: ["system", "notosansmono"],
} as const;
```

Each local font records its family, file path, weight, and format. `FontProvider` behaves as follows:

- Every role defaults to `system`, which triggers no font request at all.
- Hovering or focusing a font option preloads it without applying it.
- On an actual switch it waits for `face.load()` before writing the CSS variable, avoiding a reflow caused by `font-display: swap`.
- The choice is stored in `localStorage` and restored on the next visit.

Chinese glyphs do not participate in switching; they always fall through to `--font-cjk-*`.

## Why Chinese uses the system stack

- **Size.** A complete Chinese font is easily 2MB or more. Even a common-character subset runs into hundreds of KB, a poor trade for the first paint.
- **On-demand loading does not help here.** Chinese body text almost always needs Chinese glyphs, so it cannot be deferred the way an optional heading face can.
- **System faces are already tuned.** PingFang SC on macOS and Microsoft YaHei on Windows are adapted to their platforms for weight, spacing, and rendering.
- **The cost is cross-platform variance.** The same Chinese text looks different on macOS and Windows. Only if the design demands absolute consistency is a custom subset worth the trade.

Order matters: Latin first, Chinese second. Latin faces contain no Chinese glyphs, so the browser resolves each character to the first family in the stack that has it — `--font-cjk-sans`. Mixed Chinese/English text needs no extra handling.

## Adding a font

1. Put the font file under `public/fonts/`.
2. Register `family`, `file`, `weight`, and `format` in `FONT_LIBRARY` inside `lib/font-presets.ts`.
3. Add the id to the matching role in `FONT_OPTIONS`.
4. Add the display name under `ThemeCustomizer.fonts` in `messages/{en,zh}.json`.

No changes to `layout.tsx` or `globals.css` are needed.

**Swap the Chinese stack:** edit only `--font-cjk-*` under `:root`.

**Add a new font token** (say `--font-serif`) in three places:

1. `--app-font-serif` under `:root`;
2. `--font-serif: var(--app-font-serif)` inside `@theme inline`;
3. the role and CSS variable mapping in `lib/font-presets.ts`.

## Common questions

**`font-sans` in a component has no effect?**

Check Computed → `font-family` in DevTools first, then confirm `--font-latin-sans` exists on `<html>`. When it is absent the stack falls back to system fonts, which is expected.

**Why is there no network request after switching fonts?**

Either the font was already loaded, or you selected `system`. A request to `public/fonts/` only happens when a local face is selected and has not been loaded through `FontFace` yet.

**Why does `var()` take two arguments?**

In `font-family: var(--a), var(--b)`, a single undefined variable invalidates the entire declaration at computed-value time. `var(--font-latin-sans, var(--font-system-sans))` guarantees a complete system stack when no webfont is selected.

**Dialog and Popover use the wrong font?**

Portals render into `body`, so the inheritance chain is `body → html`. Fonts on `<html>` survive; fonts scoped to a business `div` do not. That is exactly why the family belongs on the root element.

**Chinese headings look inconsistent with the Latin ones?**

The Latin heading face defaults to a system serif and can switch to DIN 1451; `--font-cjk-heading` prefers serif Chinese faces (Songti family). On Windows it lands on SimSun, which looks noticeably different from Songti on macOS — an inherent limit of system stacks.

**How do I change the Fumadocs heading font?**

Docs page titles and MDX headings use `--font-heading` through the `#nd-page :is(h1, h2, h3, h4, h5, h6)` rule at the end of `globals.css`. Switch the heading font option; no Fumadocs component changes are needed.
