Tailwind CSS is the default styling layer in this project. Every component generated by shadcn/ui depends on Tailwind utilities and CSS variables, so keeping `components/ui/` means keeping Tailwind.

<Callout type="warn" title="Tailwind is a hard requirement for shadcn">
The classes inside `components/ui/` are Tailwind utilities such as `bg-primary`, `border-border`, and `data-[state=open]:animate-in`. Removing Tailwind strips those components of their styling. "Hard requirement" means **shadcn components require Tailwind**, not that every line of business styling must be a utility class.
</Callout>

## Why Tailwind

- **Style next to structure**: one file shows the complete appearance; no jumping between JSX and CSS files.
- **Driven by CSS variables**: `bg-primary` reads `--primary`, so the theme customizer updates the whole app at once.
- **No runtime**: Tailwind generates CSS at build time; no styling runtime ships to the browser.
- **Responsive and state variants are explicit**: `md:grid-cols-3`, `data-[state=open]:bg-muted`.
- **Styles disappear with the component**: no orphaned CSS files.

## Tailwind v4 in this project

The project uses Tailwind CSS v4 and has no `tailwind.config.js`. The entry point is `app/[locale]/globals.css`:

```css
@import "tailwindcss";
@import "tw-animate-css";
@import "shadcn/tailwind.css";
@import "fumadocs-ui/css/shadcn.css";

@custom-variant dark (&:is(.dark *));

@theme inline {
  --color-background: var(--background);
  --color-primary: var(--primary);
  --radius-lg: var(--radius);
}
```

- `@import "tailwindcss"` loads Tailwind v4.
- `@theme inline` maps CSS variables to Tailwind color and radius utilities.
- `@custom-variant dark` makes `dark:` follow `<html class="dark">`.
- `fumadocs-ui/css/shadcn.css` maps the docs `--color-fd-*` variables to the same shadcn tokens.

## Common patterns

```tsx
<div className="flex flex-col gap-4 rounded-lg border border-border bg-card p-6">
  <h2 className="text-lg font-semibold text-card-foreground">Title</h2>
  <p className="text-sm text-muted-foreground">Description</p>
</div>
```

Rules:

| Case | Prefer |
| --- | --- |
| Colors | `bg-background`, `text-foreground`, `border-border`, `text-primary` |
| Spacing | `gap-2`, `p-4`, `mt-6`; stack with `flex flex-col gap-*` |
| Dimensions | `size-4` when width equals height; avoid `h-4 w-4` |
| Conditional classes | `cn()`; no manual template-string ternaries |
| Icons | Let Button/menu components size them; avoid extra `size-4` |
| Dark mode | Semantic tokens; no manual `dark:bg-zinc-900` |

<Callout type="warn" title="Do not build dynamic class names">
Tailwind scans source at build time. `bg-${color}-500` produces no CSS. Use CSS variables, inline styles, or a complete pre-defined class map for dynamic colors.
</Callout>

## When to use native CSS

Tailwind does not mean "every style must be a utility class". Native CSS is appropriate for:

- Complex keyframes, `@property`, or `@supports` combinations.
- Overriding third-party internals such as Mermaid SVG.
- Global browser behavior: print styles, scrollbars, selection, autofill.
- Shared styling that becomes harder to read as utilities.

Put it in:

```text
app/[locale]/globals.css   # global behavior, theme variables, third-party overrides
components/<name>.css      # local styles for one complex component
```

Even in native CSS, reference theme variables instead of hardcoding colors:

```css
.custom-surface {
  background: var(--card);
  color: var(--card-foreground);
  border: 1px solid var(--border);
  border-radius: var(--radius);
}
```

Light/dark mode and theme presets then apply to native CSS too.

## How it relates to shadcn

| Concern | Owner |
| --- | --- |
| Component structure and behavior | shadcn/ui + Radix |
| Style utilities | Tailwind CSS |
| Color, radius, shadow tokens | `app/[locale]/globals.css` + theme customizer |
| Variant management | `class-variance-authority` (used inside shadcn) |
| Class merging | `cn()` (`clsx` + `tailwind-merge`) |

## Checklist

- Are new colors semantic tokens?
- Did `space-x-*` / `space-y-*` slip in? Use `flex` + `gap-*`.
- Are hex values or Tailwind palette colors hardcoded?
- Did you edit `components/ui/` just to override one style?
- Are complex styles in `globals.css` or a local CSS file instead of a long arbitrary-value chain?
