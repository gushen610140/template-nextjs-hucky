## Permissions and entry points

| Role | Permission | What they see |
| --- | --- | --- |
| User | `file:own` | "Files → My files" in the sidebar |
| Admin | `file:manage` | "My files" and "All files" |

New users get the `user` role automatically. If an account has no file entry, an administrator should assign a role in `/dashboard/users`, or confirm `file:own` is attached to that role.

## Uploading

- Click "Upload files" to pick one or more files.
- Drag files from the OS file explorer onto the page; a drop overlay appears and releasing uploads them.
- Drop onto a **folder row** to upload straight into that folder.
- Each file gets its own progress bar. The limit is 200 MB per file.

Uploads go straight from the browser to storage, so the progress bar reflects the real transfer. After the transfer the app re-checks the object size and reports "The upload did not complete" if verification fails.

## Folders

Folders are virtual groupings. They do not create directories in object storage and never copy or move objects.

| Action | How |
| --- | --- |
| Create | "New folder" button, or right-click empty space → "New folder" |
| Open | Double-click the folder row |
| Go back | Click any breadcrumb level, or "Up one level" |
| Move a file | Drag a file row onto a folder row, or onto any breadcrumb level |
| Rename | Pencil button, or right-click → "Rename folder" |
| Delete | Trash button, or right-click → "Delete folder" |

Deleting a folder differs from deleting a file:

- The folder itself is **permanently removed**.
- Every file in the folder and its subfolders is **soft-deleted** (records kept, objects cleaned up best-effort).
- Sibling folders cannot share a name; duplicates are rejected.

## Search, sort, and pagination

- The search box matches **file names and folder names**. Inside a folder, a keyword searches the owner's whole tree rather than only the current level.
- Click "Name", "Size", or "Uploaded" to sort; click again to flip direction. Folders always stay above files, sorted by name.
- The list shows 20 files per page, and paging keeps the search term, sort, and folder.

## Context menu

| Target | Items |
| --- | --- |
| File row | Rename, download, delete |
| Folder row | Rename folder, delete folder |
| Empty space | New folder |

Right-clicking inputs, buttons, or breadcrumbs keeps the browser's default menu.

## Admin view

"All files" starts as a flat list of every user's files with search, sort, and pagination. The "All users" button opens a dialog:

- Picking a user switches the page into that user's folder tree, with folders, uploads, creation, drag-to-move, and context menus all enabled.
- Uploads and new folders are written to the selected user, not the admin.
- Choosing "All users" returns to the flat view.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| Upload fails with a CORS error | Bucket CORS is missing the origin or does not allow `PUT` |
| Upload fails with `SignatureDoesNotMatch` | `RUSTFS_ENDPOINT` differs from the host the browser calls |
| Download returns 403 | The presigned URL expired (15 minutes); click download again |
| No file entry in the sidebar | The current role lacks `file:own` |
| Dragging does nothing | Only file rows are draggable; folder rows are drop targets |
