`feishu-bridge` is a project-level OpenCode plugin. Its main job is to **push recent code changes to Feishu**: it watches the local `main` branch, captures configured pages when a new commit lands, and sends a commit summary plus screenshots so customers or teammates can see what changed.

The next step is to connect it to customer groups and pair it with a preview environment for a commit → push → preview → accept loop.

```text
new main commit
  → plugin polls the git ref
  → reuse or start the dev server
  → Playwright captures configured pages
  → commit summary + screenshots
  → Feishu chat / customer group
```

## What gets sent

For each new commit on `main`, the plugin sends:

1. A text summary with the short commit and the captured pages.
2. One PNG per page.

Screenshots live in `.screenshots/commits/` and are overwritten each run. On failure it sends a text error instead and writes the details to the log.

## Quick start

<Steps>

<Step>
### Create the Feishu app

Create a custom app on the Feishu Open Platform, enable the bot capability, add the permissions and events described in [Feishu console setup](#feishu-console-setup), then publish a version.
</Step>

<Step>
### Fill in credentials

Edit `.opencode/plugins/feishu-bridge/.env` and set at least `FEISHU_APP_ID` and `FEISHU_APP_SECRET`.
</Step>

<Step>
### Install dependencies and Chromium

```powershell
npm install --prefix .opencode/plugins/feishu-bridge
bun run browser:install
```

`browser:install` downloads Chromium for Playwright. Run it once per machine.
</Step>

<Step>
### Start the connection

The plugin starts disabled. In the OpenCode TUI run:

```text
/feishu-on
```

Once the sidebar shows `connected`, the plugin starts watching `main`.
</Step>

<Step>
### Make a commit

Commit anything on `main`; within 20 seconds you should receive the summary and screenshots. The first start only records the current HEAD as a baseline and does not backfill old commits.
</Step>

</Steps>

## Configuration

Config file: `.opencode/plugins/feishu-bridge/.env` (git-ignored). System environment variables take precedence.

```bash
FEISHU_APP_ID=cli_xxxxxxxx
FEISHU_APP_SECRET=xxxxxxxx
FEISHU_ALLOWED_OPEN_ID=ou_xxxxxxxx

# change feed
FEISHU_SCREENSHOT=1
FEISHU_SCREENSHOT_PAGES=/,/docs,/login
FEISHU_SCREENSHOT_BASE=http://localhost:3000
FEISHU_SCREENSHOT_MATCH=Hucky
FEISHU_SCREENSHOT_POLL_MS=20000
```

| Variable | Required | Description |
| --- | --- | --- |
| `FEISHU_APP_ID` | Yes | App ID |
| `FEISHU_APP_SECRET` | Yes | App Secret |
| `FEISHU_ALLOWED_OPEN_ID` | No | Comma-separated open_ids allowed to use the bot; empty means unrestricted |
| `FEISHU_SCREENSHOT` | No | Set to `0` to disable the change feed |
| `FEISHU_SCREENSHOT_PAGES` | No | Pages to capture, comma-separated; defaults to `/`, `/docs`, `/login` |
| `FEISHU_SCREENSHOT_BASE` | No | Preview or local base URL; defaults to `http://localhost:3000` |
| `FEISHU_SCREENSHOT_MATCH` | No | Text the page must contain to confirm it belongs to this project |
| `FEISHU_SCREENSHOT_POLL_MS` | No | Poll interval for `main`, minimum 5000, default 20000 |

## Delivery target

The feed goes to the most recent chat that messaged the bot. If there is none yet, it goes to the first open_id in `FEISHU_ALLOWED_OPEN_ID`.

To target a customer group, add the bot to the group and send one message there. A fixed group `chat_id` option will come later, removing the dependency on “most recent chat”.

## Dev server

Screenshots need reachable pages:

- If `FEISHU_SCREENSHOT_BASE` is reachable, it is reused and never shut down.
- If not, nearby ports are checked for an existing project server and reused when found.
- Otherwise the plugin starts `next dev` and stops it after capturing.
- `next dev` allows only one instance per project; point `FEISHU_SCREENSHOT_BASE` at an existing instance on another port.

## Requirements

- The plugin runs inside the OpenCode server process and only watches after `/feishu-on`; closing the TUI and service stops the feed.
- A working Node.js and `bun` are needed to run the capture script and start the dev server.
- Chromium must be installed with `bun run browser:install`.
- Capture uses `scripts/screenshot.mjs`; you can also run `bun run screenshot` manually.

## Existing interaction features

The plugin originally drove OpenCode remotely from Feishu. That still works but is no longer the primary purpose:

- TUI commands: `/feishu-status`, `/feishu-on`, `/feishu-off`, `/feishu-restart`, `/feishu-log`.
- Feishu commands: `/help`, `/new`, `/model`, `/agent`, `/session`, `/status`, `/stop`, and more.
- Streaming cards, permission approval cards, attachments, and recall handling.

See the plugin's `README.md` for details. These will gradually narrow toward pushing and customer collaboration.

## Feishu console setup

All steps happen on the Feishu Open Platform. You must **create and publish a version** after changes.

### 1. App and bot

1. Create a custom app.
2. Under app capabilities, enable **Bot**.
3. Copy the App ID and App Secret from **Credentials & Basic Info**.

### 2. Permissions

| Scope | Purpose |
| --- | --- |
| `im:message` | Read messages |
| `im:message.p2p_msg:readonly` | Receive direct messages |
| `im:message.group_at_msg:readonly` | Receive group messages that mention the bot |
| `im:message:send_as_bot` | Send messages, cards, and images as the bot |
| `im:resource` | Download images and files |

### 3. Event subscription (long connection)

**Events & Callbacks** → **Event Subscription**:

1. Choose **Receive events through a long connection**.
2. Add these events:

| Event | Purpose |
| --- | --- |
| `im.message.receive_v1` | Remember the latest chat and receive group messages (for future todo triage) |
| `im.message.recalled_v1` | Interrupt the task when a user recalls a message |

### 4. Callback configuration

Card buttons need callbacks, which live under **Callback Configuration**:

1. Open **Events & Callbacks** → **Callback Configuration**.
2. Choose **Receive callbacks through a long connection**.
3. Add the **Card action trigger** callback `card.action.trigger`.

<Callout type="warn" title="Callbacks must respond within 3 seconds">
Feishu requires a card callback response within 3 seconds. The plugin calls `permission.reply` immediately and does not block.
</Callout>

### 5. Publish

Create and publish a version under **Version Management & Release**. Permission, event, and callback changes only take effect after publishing.

## Troubleshooting

Log file: `.opencode/plugins/feishu-bridge/debug.log`; you can also run `/feishu-log` in the TUI.

| Log | Meaning |
| --- | --- |
| `missing FEISHU_APP_ID` | `.env` is missing or unreadable |
| `websocket FAILED` | Bad credentials, unpublished app, long connection disabled, or outbound traffic blocked |
| `websocket ready` but no `message received` | Event subscription missing or app version not published |
| `screenshot: baseline recorded` | First start recorded the baseline; expected |
| `screenshot: no feishu target` | No chat or open_id available; message the bot once |
| `screenshot: FAILED` | Capture or delivery failed; read the error on the same line |
| `dev server 启动失败` | A `next dev` instance already exists; point `FEISHU_SCREENSHOT_BASE` at it |
| `rpc register FAILED` | RPC contract or registration problem |

## Roadmap

- **Customer group feed**: a fixed group `chat_id` with per-group content and cadence.
- **Preview environment**: point `FEISHU_SCREENSHOT_BASE` at a preview deployment so customers preview before accepting.
- **Group message triage**: watch customer feedback, summarize it with AI, and file it into the project todo list.
- **Collaboration loop**: developers confirm requirements, progress, and acceptance with customers through Feishu and AI.

These are not implemented yet; this page will be updated as they land.

## Limitations

- Feishu and Lark only; no WeCom or DingTalk.
- The feed only covers local commits on `main`; it does not watch remote updates or `git push`.
- Delivery targets the most recent chat; there is no per-group configuration yet.
- It depends on a running OpenCode server; stopping the service stops the feed.
